4. Shader Program 与 EntryPoint 声明

一个 Shader 文件可以声明多个 Program。每个 Program 通过 marker struct 集中声明阶段入口和 Variant Group；入口函数本身不需要 [shader("vertex")]、[shader("fragment")] 等 Attribute。

SHADER_PROGRAM(
    ShaderProgramTest,

    SHADER_VS(TestVS)
    SHADER_PS(TestPS)

    SHADER_MACRO(MATERIAL_LIT, MATERIAL_UNLIT)
    SHADER_MACRO(_, FOG_ON)
);

上例的 ProgramId 是区分大小写的字符串 "ShaderProgramTest"，即 marker struct 的声明名称。编译器不得将它改写为全限定名、hash 或其他派生值。同一个 Shader Resource 中的 ProgramId 必须唯一；即使声明位于不同 namespace，也不能重复使用同一个 name。重命名 name 等同于更改 Program 身份，会使原身份对应的 artifact 失效。

ProgramId 读取契约：宿主只从根 Module 直接子声明的公共 Slang 反射对象读取名称，并调用 DeclReflection::getName()。返回的名称必须立即复制为引擎拥有的 UTF-8 字符串；返回 null 或空字符串时编译失败。契约中不存在 SimpleName 属性或别名，也不得改用 Slang 内部 AST API 推导名称。

声明语义
SHADER_PROGRAM(ShaderProgramTest, ...)声明一个完整 Shader Program，并将 ProgramId 定义为 "ShaderProgramTest"。
SHADER_VS(TestVS)vertex 阶段入口函数名为 TestVS。
SHADER_PS(TestPS)fragment 阶段入口函数名为 TestPS；其他阶段使用对应的 SHADER_* 宏。
SHADER_MACRO(A, B)必选互斥组；省略该组时默认选择声明中的第一个宏 A。
SHADER_MACRO(_, FOG_ON)含空选择的互斥组；_ 表示该组不定义任何实际宏。

Program 发现范围与 Stage 校验

Program 发现只针对当前 Shader Resource 对应根 Module 的直接声明执行：

  • 只读取根 Module 直接声明的 SHADER_PROGRAM marker struct；Program 必须声明在根作用域。
  • 不递归进入根 Module 内的 namespace。namespace 内声明的 marker struct 不会被注册为 Program。
  • 不发现 imported Module 中的 Program；import 只提供函数、类型和公共代码。
  • ProgramId 始终是 DeclReflection::getName() 返回的 SHADER_PROGRAM 简单声明名，namespace 不参与身份。同一个 Shader Resource 内不得出现相同名称，即使符号位于不同 namespace。
Program 类型Stage 契约非法情况
Compute Program 必须且只能声明一个 CS。 缺少 CS、重复 CS，或同时包含任意 Graphics Stage。
Graphics Program 每种 Graphics Stage 最多一个入口，且必须声明一个 PS；声明 HS 或 DS 时必须同时声明另一项。 缺少 PS、任一 Stage 重复、HS/DS 只出现一个，或同时包含 CS。

重复 Stage 和非法 Stage 组合在生成 Variant 笛卡尔积及目标代码之前直接报错，不能通过选择不同 Variant 将同一 Program 拆成不同的 Stage 结构。

EntryPoint 参数限制（已确认）

当前版本采用单根反射模型，不支持 EntryPoint 自有的 uniform 或 resource 参数。入口参数只用于描述 Stage 接口：

  • 只允许 Slang 反射为 varying input、varying output 或 system-value 的参数，例如 vertex attribute、fragment output、SV_DispatchThreadID 等阶段输入输出。
  • 任何在 EntryPoint 参数中分配 ordinary/uniform 数据、Texture、Buffer、Sampler、ConstantBuffer、ParameterBlock 或其他 descriptor/register-space 资源的声明均为非法；即使 Slang 语言本身接受该声明，SolarEngine Shader 编译也必须失败并报告具体入口与参数名称。
  • 所有运行时可设置的 uniform 和资源必须声明在当前 Module 的全局参数作用域，或声明为该根作用域下的显式 ConstantBuffer/ParameterBlock 子对象。
  • SLC2 不创建 EntryPoint 专属 ParameterBlock，也不序列化 entryPointBlockId；所有 Stage 共享 Program 的唯一根 Layout。

顶点输入声明（已确认）

顶点输入分为两层：Vertex EntryPoint 的逻辑输入签名描述 Shader 需要什么，Program 级顶点缓冲布局描述这些数据如何存放。源码采用 A 方案，在 SHADER_PROGRAM 中分别显式声明 Binding 与 Element；Location 只来自 Slang Reflection，不在源码布局中重复声明。

SHADER_PROGRAM(
    SurfaceProgram,

    SHADER_VS(SurfaceVS)
    SHADER_PS(SurfacePS)

    SHADER_VS_INPUT_BINDING(0, 32, PER_VERTEX, 0)
    SHADER_VS_INPUT_ELEMENT(POSITION, 0, R32G32B32_Float, 0, 0)
    SHADER_VS_INPUT_ELEMENT(NORMAL,   0, R10G10B10A2_UNorm, 0, ALIGN)

    SHADER_VS_INPUT_BINDING(3, 64, PER_INSTANCE, 1)
    SHADER_VS_INPUT_ELEMENT(INSTANCE_TRANSFORM, 0, R32G32B32A32_Float, 3, 0)
);
声明字段与语义
SHADER_VS_INPUT_BINDING(slot, stride, inputRate, instanceStepRate)声明一个物理 Vertex Buffer Slot。stride 是完整顶点/实例记录的字节步长，允许显式间隙和尾部填充；PER_VERTEX 必须使用 step rate 0，PER_INSTANCE 首期必须使用 step rate 1。
SHADER_VS_INPUT_ELEMENT(semantic, semanticIndex, format, slot, offset)声明一个物理 Attribute。Semantic 按 ASCII 大小写不敏感匹配并在产物中转为大写规范形式；format 使用稳定的 SolarEngine PixelFormat 名称；offset 是非负字节偏移或 ALIGN。
  • 同一 Slot 只能声明一个 Binding；每个 Element 引用的 Slot 必须存在。Slot 可以稀疏，例如同时使用 0 和 3；Slot 编号不是 Semantic、Location 或参数序号。
  • Slot 必须小于引擎 GPU_MAX_VB_BINDED，Element 总数不得超过 VERTEX_SHADER_MAX_INPUT_ELEMENTS；生成 required Slot mask 前必须先验证位宽与引擎上限。
  • ALIGN 只表示紧接同一 Slot 的前一个 Element，即 previous.offset + previous.formatByteSize；该 Slot 的第一个 Element 使用 ALIGN 时 offset 为 0。它不增加自然对齐或 16 字节对齐。
  • Element 范围不得重叠，并且必须满足 offset + formatByteSize <= stride。Stride 不由 Element 推导，因此布局可以表达尾部 padding。
  • Program 的物理顶点缓冲布局对全部 Target 与 Variant 固定。Variant 即使不读取某项输入，也不能增加、删除或修改 Binding/Element；需要 Static、Skinned、PositionOnly 等不同布局时必须声明不同 ProgramId。
  • 所有声明的 Binding/Element 都是必需输入，不存在 optional Element 或自动默认 Vertex Buffer。Mesh 缺少其中任一数据时与该 Program 不兼容，应在导入阶段补齐数据或选择其他 ProgramId。
  • 没有 Vertex Stage 的 Program 不得声明顶点布局；只使用 SV_VertexID、SV_InstanceID 等 system-value 的 Vertex Stage 可以声明空布局。

宏到 Slang Attribute 的展开

[__AttributeUsage(_AttributeTargets.Struct)]
struct SolarShaderProgramAttribute {}

[__AttributeUsage(_AttributeTargets.Struct)]
struct SolarShaderStageAttribute
{
    string stage;
    string entryPoint;
};

[__AttributeUsage(_AttributeTargets.Struct)]
struct SolarShaderMacroGroupAttribute
{
    string members;
};

[__AttributeUsage(_AttributeTargets.Struct)]
struct SolarShaderVertexInputBindingAttribute
{
    int slot;
    int stride;
    string inputRate;
    int instanceStepRate;
};

[__AttributeUsage(_AttributeTargets.Struct)]
struct SolarShaderVertexInputElementAttribute
{
    string semantic;
    int semanticIndex;
    string format;
    int slot;
    string offset;
};

#define SHADER_VS(entry) [SolarShaderStage("vertex", #entry)]
#define SHADER_PS(entry) [SolarShaderStage("fragment", #entry)]
#define SHADER_MACRO(...) [SolarShaderMacroGroup(#__VA_ARGS__)]
#define SHADER_VS_INPUT_BINDING(slot, stride, inputRate, stepRate) [SolarShaderVertexInputBinding(slot, stride, #inputRate, stepRate)]
#define SHADER_VS_INPUT_ELEMENT(semantic, semanticIndex, format, slot, offset) [SolarShaderVertexInputElement(#semantic, semanticIndex, #format, slot, #offset)]
#define SHADER_PROGRAM(name, context) [SolarShaderProgram] context struct name {}
  • SHADER_MACRO 必须直接使用 #__VA_ARGS__ 保留原始 token；不能先经二级宏展开。
  • SHADER_PROGRAM 展开出的 [SolarShaderProgram] 是唯一 Program marker；因此没有 Stage 的 Program 也会被发现并按 Stage 契约报错，绝不能静默忽略。
  • 宿主通过 IModule::getModuleReflection() 遍历根级声明，再通过 getUserAttributeCount() 和 getUserAttributeByIndex() 分类 Program、Stage 与 Macro Group Attribute。
  • 宿主使用 IModule::findAndCheckEntryPoint(entryPoint, stage, ...) 查找并检查没有 [shader] 标记的入口函数。
  • 找到入口后必须检查其参数布局类别；只接受 varying/system-value 输入输出，拒绝 EntryPoint uniform/resource 参数。
  • Program、Stage、Variant Group 与顶点缓冲布局声明不得由该 Program 自己的 Variant 宏控制，所有 Variant 必须得到稳定的 Program 结构。

5. Variant Group、默认项与规范化

声明语义

声明默认选择自动全量编译
SHADER_MACRO(A, B, ...) 调用者省略该组时选择第一个宏 A。 生成 A、B 等全部实际宏分支。
SHADER_MACRO(_, A, B, ...) 调用者省略该组时选择空宏状态。 生成空宏分支以及 A、B 等全部实际宏分支。

_ 是参与笛卡尔积的真实选择状态，但不是预处理器宏。选择 _ 时仍然生成、编译和缓存一个 Variant，只是不向 Slang 传递该组宏，也不把 _ 写入 variant 字符串。

G0 = { MATERIAL_LIT, MATERIAL_UNLIT }
G1 = { _, FOG_ON }

VariantCount = |G0| × |G1| = 4
DefaultVariant = MATERIAL_LIT

MATERIAL_LIT
MATERIAL_UNLIT
FOG_ON;MATERIAL_LIT
FOG_ON;MATERIAL_UNLIT

SHADER_MACRO(_, FOG_ON) 单独存在时：
  Defines = {}          -> variant = ""
  Defines = { FOG_ON }  -> variant = "FOG_ON"

数据模型

struct ShaderVariant
{
    Set<String> Defines;
};

struct ShaderVariantGroup
{
    Array<String> Members;       // 不包含 "_"，保持源码声明顺序
    bool HasUndefinedChoice;
    String DefaultMember;        // 必选组为 Members[0]；含 "_" 的组为空
};

统一规范化算法

BuildVariants(Groups):
  1. 将 "_" 转换为 HasUndefinedChoice，并从 Members 中移除。
  2. 校验每组原始选项数至少为 2，且实际宏名在 Program 内全局不重复。
  3. 对所有组做笛卡尔积。
  4. 实际宏选择加入 Defines。
  5. 空选择不加入宏名，但仍保留一个物化 ShaderVariant。
  6. 没有任何组时，生成一个 Defines = {} 的 Variant。

NormalizeVariant(Groups, RequestedDefines):
  1. 拒绝未声明宏、保留哨兵 "_"、NAME=VALUE 和同组多个成员。
  2. 缺少必选组时加入该组 Members[0]。
  3. 缺少含 "_" 的组时保持该组无宏。
  4. 将补全后的实际宏集合交给 SerializeVariant。

SerializeVariant(Defines):
  1. 宏名区分大小写并符合 [A-Za-z_][A-Za-z0-9_]*。
  2. 按宏名 UTF-8 字节序升序排列。
  3. 使用分号连接。
  4. 空集合序列化为 ""。
  • 必选组的第一个宏是实际定义，补全后必须出现在规范化 variant 字符串中。
  • 宏组之间的顺序和调用者传入宏的顺序不影响 variant；必选组内部成员顺序决定默认宏，属于 Shader 接口语义。
  • _ 在一个组内最多出现一次，可以在不同组重复；实际宏名不得在同一 Program 的不同组重复。
  • Variant 总数是所有组原始选项数的乘积，包含 _；溢出或超过项目上限时，在生成目标代码前失败。
