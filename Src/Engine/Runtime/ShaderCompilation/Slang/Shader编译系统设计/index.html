SolarEngine Slang Shader 编译系统设计

Slang-only 源码 · 多 Target 编译 · 声明式 Variant · SLC2 文本缓存 · Falcor 风格名称绑定

1. 目标与已确认决策

目标是在 SolarEngine 中以 Slang 替换新 Shader 资产的编译路径，并建立从 Shader 声明、Variant 选择、目标代码生成、反射布局、文本缓存到 Vulkan 运行时名称绑定的完整闭环。

源码语言仅使用 Slang；旧 SolarEngine .shader / HLSL Shader 资产不兼容、不迁移，也不进入新编译系统。
Target编译请求只指定操作系统平台、图形后端和 Shader Model；三者平铺在 ShaderCompileTarget 中并共同形成 TargetKey。
编译策略API/目标二进制版本、capability、优化、调试、矩阵布局、浮点模式及其他 Slang 选项由引擎统一策略固定，不是请求参数或 TargetKey 维度；策略变化通过 CompilerBuildTag 使缓存失效。
编译结果ShaderCompileResult 只返回 Success/Failed、包含 Warning/Error 的 CompileMessage 和完整 UTF-8 JSON SLC2Data；编译信息只输出当次日志、不持久化，失败时数据为空。
首个实现优先完成 Vulkan → SPIR-V；接口保留未来 DXIL、WGSL 等 Target。
Binding由 Slang 自动分配 set/binding，Shader 作者不显式指定 Vulkan binding。
运行时 API按资源全名设置 Texture、Buffer、Sampler；后续扩展其他资源类型。
资源绑定完整性所有需要写入 descriptor 的资源槽都必须在运行时显式绑定非空资源；未绑定或被设置为 null 时直接返回绑定错误，不自动补默认资源。Shader、编译器和 SLC2 均不声明 required/optional 策略。
Program 身份ProgramId 就是 SHADER_PROGRAM(name, ...) 中声明的 name。
VariantSHADER_MACRO 声明互斥组；多个组做笛卡尔积，宏只有“定义/未定义”状态。
参考模型借鉴 Falcor 的反射、ParameterBlock 和 ShaderVar 思想，不导入 Falcor/gfx 运行时。
Layout 身份一份 Layout 归属于 ProgramId × TargetKey × Variant，并由该 Variant 的全部 Stage 共享。
反射根模型每份 Layout 只有一个 rootBlockId。EntryPoint 只允许 varying/system-value 输入输出；不支持 uniform/resource 参数，全部可绑定数据必须位于 Module 全局作用域或显式 ConstantBuffer/ParameterBlock 中。
反射产物编译期从 Slang linked component 生成引擎自有 ShaderReflectionIR；运行时只从 SLC2 重建反射，不二次调用 Slang。
Layout Schemaschema = 2；逻辑 resourceRanges[] 与 rangeBindings[] 按块内 rangeIndex 完整对应，每条 mapping 再包含 0～N 个物理 descriptor 或一个子块引用。
Uniform 存储Module 全局普通数据进入根块的 defaultUniformBuffer；每个显式 ConstantBuffer/ParameterBlock 的普通数据进入该子块自己的 defaultUniformBuffer。
Push Constant首版完全不支持；Shader 一旦产生 Push Constant 反射布局即编译失败，SLC2 不序列化任何 Push Constant 字段。
数组访问支持 ShaderVar[index] 和名称路径中的 [index]；只允许正整数长度的固定数组，不支持任何无界声明。
块数组ConstantBuffer/ParameterBlock 本身不得形成数组；单个块内部的普通数据数组和资源数组仍按通用数组契约支持。
Pipeline Layout 身份pipelineLayoutFingerprint 对版本化规范文本计算完整 SHA-256，仅表示当前 Target 完整物理 Pipeline Layout 的精确相等关系。
Specializationinterface/generic 必须在编译期静态完成 specialization；不实现运行时动态 specialization。

3. 核心术语与身份层级

术语定义身份
Shader Resource一个 Shader 源文件或 Shader 资产；一个资源对应一个聚合 SLC2 文件。SLC2FileKey
Shader Program由一个 SHADER_PROGRAM marker struct 声明的完整程序及其全部阶段。ProgramId = SHADER_PROGRAM(name, ...) 中的 name
Variant Group一次 SHADER_MACRO(...) 声明的互斥选项集合。Program 内的声明顺序与成员集合
Variant每个宏组选择一个状态后形成的无值宏名集合。规范化 variant 字符串
Target操作系统平台、图形后端和 Shader Model 的平铺组合；其他编译选项由统一策略固定。TargetKey = Platform × Backend × ShaderModel
完整编译单元一个 Program 在一个 Target、一个 Variant 下的全部 Stage。ProgramId × TargetKey × Variant
Stage Record完整编译单元内部的一条阶段代码记录。EntryPoint × Stage
SLC2面向运行时的 UTF-8 JSON Shader 缓存；不保存源路径、import 路径或诊断文本。<SLC2FileKey>.slc.json

缓存身份和原子更新以“完整编译单元”为最小语义单位。Stage Record 只负责定位单个阶段，不能独立参与缓存命名；跨编译调用的增量失效策略后续设计。

12. 实施里程碑

  1. 定义 Slang-only 编译请求、结果与 backend 调度边界，新路径不包含 Legacy Shader 分流。
  2. 完成 Slang → SPIR-V → Vulkan Compute Pipeline 的最小闭环。
  3. 实现 Program/Variant Attribute 发现、显式 Variant 过滤和完整排列组合。
  4. 实现 ShaderProgramLayout、SLC2 v2 和 Texture/Buffer/Sampler 名称绑定。
  5. 联合链接 VS/PS，创建统一 graphics pipeline layout 和 descriptor sets。
  6. 补齐固定数组下标访问、固定资源数组绑定、UAV、嵌套 ParameterBlock、加速结构和 uniform 字段；无界数组不进入当前或后续既定里程碑。
  7. 建立 SolarEngine Slang 标准库并编写新的 Slang Vulkan Shader 资产；不迁移旧 .shader / HLSL Shader 资产。
  8. 按同一接口扩展 DXIL、WGSL 等未来 Target。

13. 验收标准

编译与 Program

  • 编译请求只需指定操作系统平台、图形后端和 Shader Model，即可按对应统一编译策略生成 artifact；请求中不存在 API/二进制版本、capability、Optimize、Debug、矩阵或浮点模式覆盖项。
  • ShaderCompileTarget 平铺 Platform、Backend 和 Model，不包含嵌套 ShaderTargetPlatform。相同三元组生成相同 TargetKey，任一字段变化均生成不同 Key。
  • 基线发现以空 Variant 宏集合加载根 Module；依赖 Variant 宏才能出现的 Program、Stage 或宏组声明会产生明确错误。
  • 新编译入口只接受 Slang Shader 资产，不按资产类型、语言字段或资产版本回退到 Legacy 编译器。
  • SHADER_PROGRAM(ShaderProgramTest, ...) 的根声明通过公共 Slang API DeclReflection::getName() 产生精确的 ProgramId = "ShaderProgramTest"；名称返回 null 或空字符串时编译失败，同一 Shader Resource 中的重名声明被拒绝，重命名后旧身份的 artifact 不再命中。
  • 实现新增或 SolarEngine 更新内置 Slang 时，compiler-side API 编译/链接探针必须使用工程当前可用的公共头文件与编译库通过；探针覆盖实现实际调用的 Slang API，反射语义另由最小 Shader fixture 验证，运行时不因此链接 Slang。
  • 只发现根 Module 根作用域中的 Program；namespace 和 imported Module 中的 Program 不参与编译。
  • Compute Program 只能包含一个 CS；Graphics Program 必须包含 PS、每种 Stage 最多一个入口，并要求 HS/DS 成对出现。
  • 入口函数无需 [shader]，可由 Program 声明的名称和 Stage 正确检查。
  • EntryPoint 只允许 varying/system-value 输入输出；任何 EntryPoint uniform/resource 参数都会产生包含入口和参数名称的编译错误。全部可绑定参数必须来自 Module 全局作用域或显式 ConstantBuffer/ParameterBlock。
  • 反射中出现任何 Push Constant、unknown/unbounded 数组或资源 range，或 ConstantBuffer/ParameterBlock 自身形成数组、被数组直接或间接重复实例化时，当前编译单元失败且不产生 SLC2。
  • 同一 graphics Program 的全部入口来自同一 linked component 并共享兼容布局。

Variant

  • 未设置过滤器时生成所有 Program 的完整笛卡尔积；显式过滤器只生成规范化后的指定组合。
  • 必选组省略时选择第一个宏；含 _ 的组省略时生成真实空宏 Variant。
  • SHADER_MACRO(_, FOG_ON) 全量编译同时产生 "" 和 "FOG_ON" 两个缓存 Variant。
  • 宏输入顺序不影响匹配；非法组选择、未知宏或带值宏产生明确错误。

缓存与运行时

  • CompilerBuildTag、Target 和 Variant 均参与完整编译单元身份；source/import 的跨调用精确失效、未请求单元复用与孤儿缓存清理由后续 DependencyIndex 设计处理，不列入当前验收。
  • SLC2 可确定性写入、严格校验并原子替换；失败不会破坏此前有效缓存。
  • ShaderCompileResult 只包含 Status、CompileMessage 和 SLC2Data。成功时消息可以为空或包含 Warning，且数据是完整 UTF-8 JSON SLC2；失败时消息包含 Error 且数据为空，不返回逐单元或部分 Target 结果。
  • CompileMessage 只在本次实际编译结束后输出日志，不进入 SLC2 或其他持久化数据；缓存命中不重放历史 Warning，TreatWarningsAsErrors 也不重新判定历史编译信息。
  • 每个 ProgramId × TargetKey × Variant 只保存一份共享 Layout；其全部 Stage Record 均不重复保存 Layout。
  • 每份 Layout 只有一个有效 rootBlockId；SLC2 不包含 entryPointBlockId，运行时也不会为任一 Stage 构造独立参数根。
  • SLC2 不包含独立 names 字段或重复的规范全名；运行时可从类型树中的成员局部名称确定性派生完整路径并生成名称索引。
  • 运行时能从 types[]、parameterBlocks[] 和 rangeBindings[] 重建 ShaderVar/ParameterBlock 访问链，不依赖 Slang 或 SPIR-V 二次反射。
  • types[] 使用连续且确定性分配的 ID；每个 Type Record 均包含 uniformByteSize 与 resourceRanges[]，并严格符合其 basic/struct/array/resource/parameterBlock 分支字段契约。
  • SLC2 Type Record 不包含 Slang/Falcor/Vulkan 原生枚举整数。未解析或未映射的类型、scalar、资源 shape/access 或 image format 必须使编译失败，不能写入 unknown 占位值。
  • 每个 ParameterBlock 的逻辑 resourceRanges[] 与 rangeBindings[] 按 (blockId, rangeIndex) 完整一一对应；一条 simple mapping 可以拥有多条 descriptorRanges[]，子对象 mapping 只能拥有一个有效 subBlockId。
  • 每个块满足 uniformByteSize = 0 ⇔ defaultUniformBuffer = null；全局普通数据使用根块默认 Uniform Buffer，显式 ConstantBuffer/ParameterBlock 的普通数据使用各自子块默认 Uniform Buffer，按名称写入能定位到正确的 (blockId, uniformByte)。
  • 运行时能从全部可达块的非空 defaultUniformBuffer 和 descriptorRanges[] 确定性重建 DescriptorSetLayout/PipelineLayout，不依赖序列化的 descriptorSets[]，且 SLC2 不包含 Push Constant 数据。
  • 写入 SLC2 的 linked component 已完成全部 interface/generic specialization；运行时不会因绑定资源或 ParameterBlock 而调用 Slang、改变具体类型或生成新的 Pipeline Layout。
  • 同一 struct 类型在根块的多个不同位置复用时，成员相对偏移可逐层累加得到各自正确的最终位置；不得要求序列化器复制类型或保存根绝对偏移。
  • C++ 仅按名称即可绑定 Texture、Buffer、Sampler，并支持 textures[3]、materials[2].baseColorTex 等数组元素路径；类型、语法和越界错误有明确诊断。
  • 运行时不提供 required/optional 绑定策略；所有需要写入 descriptor 的资源槽都必须显式绑定类型兼容的非空资源。未绑定或显式设置为 null 的槽位在 descriptor 提交前产生包含完整资源路径与期望类型的确定性错误，并中止对应 Draw/Dispatch；SLC2 不保存任何绑定策略、默认资源标识或 fallback 字段。
  • 固定资源数组可逐元素绑定且 descriptor 更新位置正确；所有数组/range/descriptor 数量必须是正的有限整数，无界声明在所有 Target 上均得到确定性编译错误，不能静默生成不完整缓存。
  • 单个 ConstantBuffer/ParameterBlock 内的普通数据数组和资源数组可按通用数组路径访问；块数组、以数组为元素根的块和数组元素闭包中的块实例均被确定性拒绝，Schema 中不存在块实例下标或 descriptor stride。
  • Vulkan 资源数组元素只改变 dstArrayElement，不会把数组下标加到 binding；组合资源和内部 counter 能按一条名称绑定更新其全部物理 descriptor。
  • pipelineLayoutFingerprint 始终是 64 个小写十六进制字符；物理布局相同但名称或逻辑类型图不同的 Layout 产生相同值，任一纳入规范输入的物理字段变化都会产生不同值。运行时重算验证，并在 hash 命中后深比较规范物理记录再复用 GPU 对象。
  • Vulkan validation layer 下 descriptor layout、pipeline layout 和绑定无错误。
  • 运行时不依赖硬编码 set/binding，也不要求 Shader 源码显式声明 Vulkan binding。

15. 非目标

  • 不兼容、不编译、不迁移旧 HLSL Shader 资产，也不提供 Legacy 调度或自动转换器。
  • 第一阶段不实现 D3D12、WebGPU 或其他平台专用 Target。
  • 当前阶段不设计 Cook/发布流程；SLC2 的资产打包位置、Target/Variant 裁剪、发布加载策略和文件大小上限均不属于本设计范围。
  • 当前阶段不设计或实现 DependencyIndex；其持久化内容与格式、source/import 反向索引、精确增量编译、SLC2/索引提交顺序、崩溃恢复、并发更新和缓存 GC 均留待后续处理。
  • 当前阶段不设计运行时生命周期；descriptor 分配与 dirty tracking、Pipeline 缓存、热重载交换、布局变化后的失效传播以及 GPU 对象延迟销毁均不属于本设计范围。
  • 当前阶段不实现默认资源库或任何资源 fallback；运行时不会为未绑定资源自动创建、选择或填充替代资源。
  • 不直接移植 Falcor 的 gfx、Device 或 ParameterBlock 实现。
  • 当前版本不支持 EntryPoint uniform/resource 参数或 EntryPoint 专属 ParameterBlock；EntryPoint 只承担 varying/system-value Stage 接口。
  • 当前版本不支持 Push Constant；不序列化 Push Constant 布局，也不在 Vulkan PipelineLayout 中创建 Push Constant range。
  • 不实现运行时 interface specialization、按绑定对象类型即时编译 Shader，或在运行时生成新的 specialized Pipeline/Layout。
  • 当前设计不支持任何无界数组或无界资源 range，也不启用 runtimeDescriptorArray、variable descriptor count、partially-bound、update-after-bind 等为无界容量服务的 descriptor indexing 模式。
  • 当前 schema 明确不支持 ConstantBuffer/ParameterBlock 自身形成数组，也不规划块实例索引或块 descriptor stride；单个块内部的普通数据数组以及 Texture、Buffer、Sampler 资源数组不受此限制。
  • 第一阶段不要求完成 UAV、资源数组整段批量绑定、嵌套 ParameterBlock、加速结构或 uniform 字段写入；固定数组的元素级访问与资源绑定除外。
