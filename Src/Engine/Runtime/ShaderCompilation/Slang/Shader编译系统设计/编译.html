6. 编译请求与 Target

struct ShaderCompileTarget
{
    PlatformType Platform;
    GraphicsBackend Backend;
    ShaderModel Model;
};

struct ShaderProgramVariantSelection
{
    String ProgramId;                   // SHADER_PROGRAM 中声明的 name
    Array<ShaderVariant> Variants;      // 非空；每项是一组原始宏名集合
};

struct ShaderCompileRequest
{
    String SourcePath;
    Array<ShaderCompileTarget> Targets;
    Array<ShaderProgramVariantSelection> VariantSelections;
    bool TreatWarningsAsErrors;
};

路径解析边界：ShaderCompileRequest 不允许携带 SearchPaths。根 Shader 文件、import 和 #include 的查找由编译侧 SlangShaderFileSystem 统一处理，并通过 Slang SessionDesc.fileSystem 挂接；调用方不能通过请求参数改变搜索路径或污染 Shader 编译身份。

实现基础设施约束：Shader 编译系统实现默认使用 SolarEngine 基础设施。路径和文件 IO 使用 FileSystem / File；文本与第三方 const char* 边界使用 StringAnsi 持有桥接生命周期；集合、字节缓冲、Hash、JSON、日志、断言和原子操作优先使用引擎提供的方法。STL 只允许作为第三方 ABI 无法避免的局部桥接或引擎尚无等价能力时使用，不得作为路径语义、文件 IO 或持久化格式的默认实现。控制流分支必须显式使用 {}，包括单语句 if / else / for / while。

请求状态行为
VariantSelections 未设置发现 Shader 文件中的全部 Program，并为每个 Program 编译其完整 Variant 笛卡尔积。
VariantSelections 非空只编译列出的 Program 和宏集合；未列出的 Program 不参与本次编译。
一个 Selection 的 Variants 为空非法。外层空数组已经表示“全部”，禁止用内层空数组制造第二种“全部”语义。
显式传入一个 Defines = {}只产生一个规范化组合：必选组补入第一个宏，含 _ 的组选择空宏状态。
未知或重复 ProgramId、非法宏名或组合整个请求失败，不生成部分结果。

通过校验的显式 Variant 使用 NormalizeVariant 规范化并按结果去重，因此请求中的宏顺序和重复组合不会产生重复编译单元。

编译结果与原子提交（已确认）

enum class ShaderCompileStatus : uint8
{
    Success,
    Failed,
};

struct ShaderCompileResult
{
    ShaderCompileStatus Status;
    String CompileMessage;
    Array<byte> SLC2Data; // 完整的 UTF-8 JSON 文本
};
  • ShaderCompileResult 只包含编译状态、编译信息文本和编译产物 SLC2 数据，不暴露逐编译单元状态、编译阶段、结构化 diagnostics 或缓存事务状态。
  • CompileMessage 保存本次实际编译产生的 Warning、Error 及相关编译信息，保持 Slang 或引擎输出的完整文本。
  • Status = Success 时，CompileMessage 可以为空，也可以包含 Warning；SLC2Data 必须包含当前 Shader Resource 的一份完整、已通过自检的 SLC2 文本。
  • Status = Failed 时，CompileMessage 必须包含导致失败的错误信息，并可以同时包含 Warning；SLC2Data 必须为空。
  • CompileMessage 只在本次实际编译结束后输出日志，当前不写入 SLC2 或其他持久化编译信息。缓存命中时不重放历史 Warning。
  • Array<byte> 只用于保存可直接计算 hash 和写入文件的精确 UTF-8 JSON 字节，不改变 SLC2 的文本格式身份。
  • 即使请求包含多个 Program、Target 或 Variant，也只返回一份聚合后的完整 SLC2Data；不得返回部分 SLC2 或单独的 Stage/Target 产物。
  • 当前状态枚举不包含取消或部分成功。内部仍以 ProgramId × TargetKey × Variant 为完整编译单元执行，但该粒度不属于公开结果契约。
  • ShaderCompiler 负责生成上述结果；外层 ShadersCompilation 仅在 Success 后使用完整 SLC2Data 原子替换正式文件。编译失败时不执行写入，既有有效 SLC2 保持不变。

TargetKey 身份与统一编译策略（已确认）

LogicalShaderTargetPlatform =
  PlatformType × GraphicsBackend

CanonicalTargetText =
  "SOLAR-SHADER-TARGET/v1\n"
  "platform=" + CanonicalPlatform + "\n"
  "backend=" + CanonicalBackend + "\n"
  "shaderModel=" + CanonicalShaderModel + "\n"

TargetKey =
  LowerHex(SHA-256(UTF8(CanonicalTargetText)))

CompilerBuildTag =
  Hash(
      EngineShaderCompilerRevision
    + SlangBuildTag
    + CompilerPolicyVersion
  )
  • ShaderTargetPlatform 只是“操作系统平台 × 图形后端”的逻辑概念，不定义嵌套结构或额外字段。PlatformType Platform、GraphicsBackend Backend 和 ShaderModel Model 直接平铺在 ShaderCompileTarget 中。
  • TargetKey 的唯一身份字段严格为 Platform × Backend × ShaderModel。Windows/Vulkan 与 Windows/D3D12、Windows/Vulkan 与 Linux/Vulkan、以及不同 Shader Model 均产生不同 Key。
  • 规范文本使用固定字段顺序、无 BOM UTF-8、LF 换行和最后一个 LF。Platform、Backend 使用引擎定义的稳定小写字符串；Shader Model 使用稳定的 major_minor 形式。禁止保存或 hash SolarEngine、Slang、Vulkan 等原生枚举整数。
  • 例如 platform=windows、backend=vulkan、shaderModel=6_7 的规范文本得到 TargetKey = "03af5aaf813f8ed1b1cb766e442163dc56179e2e6ede7904a0ee48457eef058a"。结果必须是完整 SHA-256 的 64 个小写十六进制字符。
  • SLC2 不单独保存可被伪造的 targetKey 字段；targets[].meta 平铺保存相同的 platform、backend 和 shaderModel，读取器按上述规则生成 Key。三个字段完全相同的 Target 在同一 Program 内只能出现一次。
  • Vulkan API、SPIR-V/DXIL/WGSL 等目标格式及版本、capability 基线、优化级别、调试信息、矩阵布局、浮点与 denormal 模式、binding shift 和其他 Slang/backend 选项全部由 CompilerPolicyVersion 对当前 Platform/Backend 固定。它们不进入 ShaderCompileTarget、Target meta 或 TargetKey，也不能由单次编译请求覆盖。
  • CompilerBuildTag 聚合引擎 Shader 编译器修订、Slang build tag 和 CompilerPolicyVersion，属于 ArtifactKey 的独立维度。任一固定默认值变化都必须提升对应修订或策略版本，使旧编译单元失效；不通过扩展 TargetKey 表达策略变化。
  • TreatWarningsAsErrors 只在本次实际调用 Slang 编译并产生 Warning 时将结果转为 Failed；Warning 文本仍写入 CompileMessage。它不改变目标身份，因此不进入 TargetKey。由于编译信息不持久化，缓存命中时不重放或重新判定历史 Warning。

Shader Model 只表达语言/功能等级。Platform × Backend 选择后端和统一编译策略，由该策略固定 Vulkan API、SPIR-V 等输出格式/版本及 capability 基线；请求不逐项覆盖这些设置。每个 Platform × Backend × ShaderModel Target 独立保存目标代码和反射布局。

7. Slang 编译流程

基线发现环境

第一次加载根 Slang Module 时，编译器尚未获得任何 Variant 选择，因此使用空 Variant 宏环境读取 Program、Stage 和 Variant Group 声明。

  • 宿主传入的 Variant defines 必须为空，即 Defines = {}；不定义任何 SHADER_MACRO 成员。
  • SHADER_PROGRAM、SHADER_VS、SHADER_PS 等框架声明宏仍由 SolarEngine Slang 标准头提供，它们不属于 Variant 宏。
  • Program、Stage 和 Variant Group 声明必须在该环境中完整可见；不能依赖某个 Variant 宏才出现。
  • 根 Module 在空 Variant 宏环境中无法加载或声明不完整时，Shader 资产直接编译失败；不引入保留的 discovery define 进行补救。
  • 基线发现状态只用于生成编译计划，不是可运行 Variant，也不写入 SLC2。

编译事务步骤

  1. 规范化资源身份：规范化 Shader 虚拟资源路径，计算 SLC2FileKey。
  2. 基线发现：以 Defines = {} 加载根 Slang Module，只遍历根作用域的直接声明，不进入 namespace 或 imported Module；对 marker struct 的 DeclReflection 调用 getName() 并复制非空 UTF-8 结果作为 ProgramId，再从 Attribute 中读取 Stage 和 Variant Group，并校验 ProgramId 唯一性与 Stage 契约。
  3. 选择 Variant：请求未设置过滤器时生成完整笛卡尔积；设置过滤器时执行默认补全、校验、规范化和去重。
  4. 创建编译环境：针对每个 Target × Variant，以目标参数、搜索路径、实际宏 defines 和自定义文件系统创建 Slang session 并重新加载 module。
  5. 检查并联合链接：按声明的名称和 Stage 调用 findAndCheckEntryPoint，并拒绝除 varying/system-value 输入输出之外的 EntryPoint uniform/resource 参数；同一 graphics Program 的全部入口必须组合到同一个 linked component。
  6. 验证 Layout 支持边界：拒绝任何 Push Constant 布局，以及 ConstantBuffer/ParameterBlock 自身形成数组或被数组直接、间接重复实例化的类型图；该编译单元失败且不产生 SLC2。
  7. 提取产物：从 linked component 获取每个 Stage 的目标代码和统一 ProgramLayout；为当前 ProgramId × TargetKey × Variant 生成一份 schema = 2 的 ID 化 ShaderProgramLayout：types[] 保存类型树、成员局部名称和 ShaderVar 相对偏移，parameterBlocks[] 为每个逻辑 resource range 生成一条 rangeBinding，再以 0～N 条 descriptorRanges[] 或一个 subBlockId 表达当前 Target 落点；各 Stage 只保存入口信息与代码。
  8. 路径解析：通过编译侧 SlangShaderFileSystem 解析根源码、source/import/include；当前阶段不持久化 DependencyIndex，source/import 路径与内容 hash 不写入 SLC2。
  9. 返回并写入：只有全部请求单元成功且聚合 SLC2 自检通过时，ShaderCompiler 才返回 Success 和完整 SLC2Data；CompileMessage 可以携带 Warning，并在编译结束后输出日志。随后由外层 ShadersCompilation 原子替换正式文件。任一单元失败都返回 Failed 和包含错误的 CompileMessage，同时清空 SLC2Data 并保留原缓存。

VS、PS 等 Stage 必须来自同一个 linked component。禁止独立编译各 Stage 后猜测自动 binding 是否兼容。

Slang API 使用门禁：Slang 已由 SolarEngine 工程接入，编译实现可直接 include 并调用公共 Slang API。本设计不负责 Slang 的工程接入、构建、部署或版本管理。实现新增或 SolarEngine 更新内置 Slang 时，必须通过 compiler-side API 编译/链接探针；探针覆盖 Program 发现、Attribute、EntryPoint、ComponentType 和 Layout adapter 实际调用的全部公共 API。探针不进入运行时，也不能替代验证反射语义的最小 Shader fixture。

9. SLC2 Shader Cache

文件粒度：一个 .slc.json 文件对应一个 Shader Resource，并聚合其中全部 Program、Target、已编译 Variant 和 Stage。文件名由规范化 Shader 资源路径的 SHA-256 生成；顶层不保存 Shader 路径或 shaderId。

9.1 运行时数据结构

SLC2 文件名 =
  LowerHex(SHA-256(UTF8(CanonicalShaderResourcePath))) + ".slc.json"

SLC2
  format
  programs[]
    programId
    variantGroups[]          // Program 级，只保存一次
      members[]              // 实际宏，保持声明顺序
      default                // 第一个宏或 null
    targets[]
      meta                    // platform / backend / shaderModel
      variants[]
        variant
        layout                  // 当前 Variant 的全部 Stage 共享
          schema = 2
          pipelineLayoutFingerprint
          rootBlockId
          types[]               // 类型树、成员局部名称、相对偏移与逻辑 resourceRanges
          parameterBlocks[]
            elementTypeId
            uniformByteSize
            defaultUniformBuffer
            rangeBindings[]     // 每个 logical range 恰好一条
              rangeIndex
              flavor
              descriptorRanges[] // 0..N 个当前 Target 物理 descriptor
              subBlockId
        stages[]
          PROG
            entryPoint
            stage
            code
数据写入 SLC2职责
format / programs / targets / variants / stages是运行时选择 Program、Target、Variant，使用共享 Layout 创建 Pipeline Layout 和各阶段 Shader。
variantGroups是运行时执行与编译期相同的默认补全、校验和 Variant 匹配。
DependencyIndex否当前阶段不设计或持久化；SLC2 不加入依赖索引字段。
编译信息（Warning/Error）否只随当前实际编译调用返回，并在编译结束后输出日志；不写入 SLC2 或外部编译信息，缓存命中时不重放。

9.2 缓存键与失效层级

CanonicalShaderResourcePath =
  NormalizeShaderResourcePath(ShaderResourcePath)

SLC2FileKey =
  SHA-256(UTF8(CanonicalShaderResourcePath))

ArtifactKey = Hash(
    SLC2FileKey
  + source/import content hashes
  + CompilerBuildTag
  + ProgramId
  + TargetKey
  + normalized variant string
)

StageRecordKey = EntryPoint × Stage
  • ShaderResourcePath 是包含资源命名空间和扩展名的引擎虚拟路径，不是操作系统绝对路径。
  • 路径统一为 UTF-8、/ 分隔符和资源系统规定的大小写形式；消除重复分隔符和 .，拒绝 ..、盘符和 UNC。
  • ProgramId 按 UTF-8 编码的原始字符串参与 ArtifactKey 计算，不进行 hash、大小写折叠或全限定名改写。
  • CompilerBuildTag 聚合引擎 Shader 编译器修订、Slang build tag 和统一 CompilerPolicyVersion；任何默认编译策略变化都会使依赖它的完整编译单元失效。
  • SLC2FileKey 只定位聚合文件；ArtifactKey 标识一个完整 ProgramId × TargetKey × Variant 单元。
  • ArtifactKey 永远不包含 EntryPoint 或 Stage。任何 Stage 变化都使整个编译单元失效。
  • 资源移动或重命名会产生新文件名；旧文件清理属于后续缓存管理与 GC 设计，当前阶段不处理。
  • 路径规范化规则变化时，必须提升格式 Minor 版本或清空该版本缓存命名空间。

9.4 文本与结构约束

  • 文件必须是无 BOM 的 UTF-8、LF 换行和合法 JSON；禁止注释、重复 key 和浮点数。
  • 写入器固定字段顺序并使用两个空格缩进；读取器不依赖空白格式。
  • 顶层只能包含 format 和 programs；不得写入 shaderId、sourcePath 或 pathHash。
  • 每个 Program 必须包含唯一 programId、variantGroups 和非空 targets；没有宏组时使用空数组。
  • programId 必须逐字等于对应 SHADER_PROGRAM 的 name，区分大小写，是合法 Slang 标识符，并且在当前 Shader Resource 的 programs[] 中唯一。
  • variantGroups.members 只保存实际宏并保持声明顺序；必选组的 default 等于 members[0]，含 _ 的组使用 null。
  • 每个 Target 包含共享 meta 和非空 variants。meta 必须且只能包含稳定小写字符串 platform、backend 和规范 shaderModel；不得保存 API/二进制版本、capability、optimize/debug 或其他统一编译策略字段。
  • 读取器按第 6 节的规范文本从 meta 生成由 64 个小写十六进制字符组成的 TargetKey；同一 Program 内 Key 唯一，重复的 Platform × Backend × ShaderModel Target 为格式错误。
  • 同一 Target 内规范化 variant 字符串唯一。每个 Variant 必须包含 variant、一份共享 layout 和非空 stages。
  • 每个 Stage 只包含 entryPoint、stage 和 code；不得重复保存 variant、layout、独立 names 或 entryPointBlockId 字段。
  • Layout 必须包含 "schema": 2、唯一且有效的 rootBlockId、非空 types、非空 parameterBlocks 和 pipelineLayoutFingerprint；所有运行时可绑定参数必须从该根块沿成员或 subBlockId 可达。
  • Layout 不得包含 pushConstants 或等价字段。Slang 反射一旦包含 Push Constant，该编译单元必须在写入缓存前失败。
  • typeId 与 blockId 是 Layout 局部 ID；所有引用必须存在。写入器使用从 0 开始的连续 ID，读取器不得依赖 JSON 数组下标与 ID 恰好相同。
  • members[].offset 的所有有效分量必须相对于直接父类型生成；读取器从块根零偏移逐层累加。写入器不得把相对根 ParameterBlock 的绝对偏移混入成员记录。
  • 同一 struct 内成员局部名称必须唯一。SLC2 不保存完整资源路径；运行时从根块沿成员局部名称确定性派生完整路径，并拒绝派生出的重复路径或歧义短名称。
  • 可绑定名称路径由成员标识符、. 和十进制 [index] 组成；写入器不保存展开后的数组元素路径，读取器按类型树校验并解析下标，已解析的规范路径可以进入运行时名称索引。
  • resourceRanges[] 的数组顺序定义类型内 rangeIndex；baseIndex 是当前类型统一逻辑资源槽空间的偏移，不是 set/binding，也不是按 CBV/SRV/UAV/Sampler 分类的偏移。固定数组按已确认的 count/baseIndex 乘法规则聚合。
  • kind = "resource" 的 Type Record 必须包含非空 resourceRanges[]，完整描述该资源直接拥有的主逻辑 range 和内部辅助 range；空数组为格式错误。非数组只读 Texture2D 的直接主 range 为一条 textureSrv、count = 1、baseIndex = 0 的记录，资源数组由外层 array Type Record 聚合。
  • kind = "parameterBlock" 的 Type Record 必须包含且只包含一条 count = 1 的逻辑容器 range，其 resourceKind 与 containerKind 一致；块内容 ranges 位于 elementTypeId 指向的类型中，不能混入容器记录。
  • 辅助 counter range 的 ownerRangeOffset 是当前 Type Record 内主 range 的绝对局部索引；Resource 的 auxiliaryRanges[].rangeOffset 是从主 range 到辅助 range 的正向相对偏移。Struct 聚合时前者随字段起始 range 重定位，Array 聚合时 range 索引关系不变。
  • 只允许固定数组与固定资源 range；elementCount、resourceRanges[].count 和物理 descriptorCount 必须是正的有限 uint32。Schema 不包含 unbounded 字段；Slang 返回 SLANG_UNBOUNDED_SIZE、SLANG_UNKNOWN_SIZE 或等价数量时必须在写入缓存前失败。
  • 每个 ParameterBlock 的 rangeBindings[].rangeIndex 必须唯一并完整覆盖其 elementTypeId 根类型的全部 resourceRanges[]，所以二者长度必须相等；完整映射身份是 (blockId, rangeIndex)。
  • flavor = "simple" 时必须给出非空 descriptorRanges[] 且 subBlockId = null；每条 descriptor mapping 必须包含 role、绝对 set/binding、descriptorType、正的有限 descriptorCount、stageMask 和 flags。Schema 2 固定 arrayElementBase = 0、logicalElementStride = 1 且 descriptorCount = 对应 logical range.count，不接受其他仿射映射。
  • flavor = "constantBuffer" 或 "parameterBlock" 时必须给出有效 subBlockId 且 descriptorRanges = []。块图必须从根完全可达且无环；不同物理出现位置不得仅因 elementType 相同而错误共用 blockId。
  • 每个块必须满足 uniformByteSize = 0 ⇔ defaultUniformBuffer = null；字节大小大于 0 时映射必须存在且 role = "uniformData"。普通数据只通过所属块的默认 Uniform Buffer 存储。
  • parameterBlock.elementTypeId 不得直接指向数组；任何数组的元素类型闭包都不得包含 ConstantBuffer/ParameterBlock。单块内部的普通数据数组和资源数组仍是合法形态。
  • 同一物理 (set, binding) 只能有一个写入所有者；重复记录只有在规范化阶段合并为同一 descriptor 定义与 stage mask 后才可写入。descriptor 类型、有限数量、flags 和 Stage 集合必须与逻辑 range、当前 Target 的统一编译策略及目标代码一致。
  • 禁止增加独立顶层 backend、扁平 names 或 descriptorSets[] 数据；它们分别由 Target、类型树和全部可达物理 descriptor 记录确定。
  • 禁止在 SLC2 的任意层级增加 bindingRequirement、required、optional、默认资源标识或 fallback 策略字段；统一的资源绑定完整性校验属于运行时行为，不属于 Shader Cache 数据。
  • 枚举使用稳定的小写字符串；无效或不存在的偏移/绑定使用 JSON null，不得序列化 Slang、Falcor、SolarEngine 或 Vulkan 的原生枚举整数和哨兵值。
  • pipelineLayoutFingerprint 按 8.11 的版本化规范文本计算完整 SHA-256，必须是 64 个小写十六进制字符；读取器必须重算校验。ProgramId 是名称字符串，不是 hash。
  • code.data 使用无空白的标准 Base64；解码后同时校验 byteLength 与 SHA-256。
  • 空宏 Variant 使用 "variant": ""，仍然包含一份共享 Layout 和完整 Stage 集合，写入器不得省略。

11. 依赖索引与增量编译（当前阶段不设计）

DependencyIndex（后续事项）

范围决定：当前阶段不设计或实现 DependencyIndex。其持久化内容与格式、source/import 反向关联、精确增量复用、SLC2 与索引的提交顺序、崩溃恢复、并发更新和缓存 GC 均留待后续处理。

  • SLC2 继续只保存运行时所需数据，不加入 source/import 路径、内容 hash、CompileMessage 或依赖索引字段。
  • 运行时加载 SLC2 不依赖 DependencyIndex。
  • 当前设计不承诺跨编译调用复用依赖索引、由 import watcher 精确定位 Shader Resource，或自动清理孤儿缓存。

部分请求与聚合文件更新边界

本节只保留请求级原子更新原则。未请求单元的有效性判断与增量合并依赖后续 DependencyIndex 设计，当前不形成实现契约。

  1. 显式 VariantSelections 只定义本次需要编译的完整编译单元。
  2. 未请求单元如何验证、保留或删除，依赖未来的依赖索引与增量编译策略，当前不作规定。
  3. 所有请求单元成功后，生成并自检完整 SLC2Data；外层 ShadersCompilation 再用其原子替换正式 SLC2。
  4. 任一请求单元失败时返回 Failed 和包含完整错误的 CompileMessage，同时保证 SLC2Data 为空；不提交部分更新并保留此前有效文件。
