8. 反射 Layout 与运行时名称绑定

Slang 自动生成 descriptor set/binding。SolarEngine 编译侧从每个 linked component 的统一 ProgramLayout 构造可重建 Falcor 风格运行时反射对象的文本布局。Layout 的归属粒度固定为 ProgramId × TargetKey × Variant，同一 Variant 的全部 Stage 共享一份：

8.0 当前契约总览

本节记录当前讨论形成的最终口径；8.1–8.13 给出具体规则。若早期讨论结论与本节冲突，以本节和后续详细条款为准。

归属层级Layout 位于 targets[].variants[].layout，不是 Program 级、Stage 级或整个 Target 共用；同一 Variant 的全部 Stage 共享。
根模型每份 Layout 只有一个 rootBlockId，名称查找和 ShaderVar 累计偏移均从该根块开始；不存在 EntryPoint 专属反射根或 entryPointBlockId。
生成边界编译期从已联合链接、已静态 specialization 的 Slang ComponentType 生成引擎自有 ShaderReflectionIR。
运行时边界运行时从 SLC2 重建不可变 ShaderProgramReflection；每个 ShaderProgramInstance 再独立创建一棵以 rootBlockId 为根的 ShaderParameterBlock 树，并从该树取得可读写的 ShaderVar，不依赖 Slang 或 SPIR-V 二次反射。
Falcor 风格绑定模型借鉴 Falcor 的 ParameterBlock → ShaderVar → 提交快照 分层，但不导入 Falcor/gfx。ParameterBlock 只保存逻辑 uniform/资源/子块状态；ValidateAllBindings() 产生不可变 ShaderBindingSnapshot；后端 Descriptor Writer 只消费该快照。
双重地址语义类型树保存逻辑 ShaderVar 地址；每个逻辑 resourceRange 对应一条 rangeBinding，而该记录可包含 0～N 个当前 Target 的物理 descriptorRanges[]。
名称删除独立 names[]。SLC2 只保存成员局部名称，运行时派生完整路径和 NameId → ShaderVarLocation 索引。
成员偏移uniformByte/resourceRange/resourceIndex 相对于直接父类型保存，运行时逐层累加；跨子 ConstantBuffer/ParameterBlock 后从子块根重新累计。
Uniform 存储普通数据只使用其所属块的 descriptor-backed defaultUniformBuffer；uniformByteSize = 0 时该映射为 null，大于 0 时必须存在有效映射。
Push Constant当前版本不支持且不序列化；反射中出现任何 Push Constant 布局均使编译单元失败。
数组支持 ShaderVar[index]、textures[3] 和嵌套数组路径；只允许正整数长度的固定数组。任何 unknown/unbounded 数量均编译失败，Schema 不保存 unbounded 字段。
块数组禁止 ConstantBuffer/ParameterBlock 自身形成数组，包括通过外层聚合间接重复块实例；单块内部普通数据或资源数组不受此限制。
资源绑定完整性不存在逐资源的 required/optional 语义或绑定策略。所有需要写入 descriptor 的资源槽都必须在运行时显式绑定类型兼容的非空资源；未绑定或为 null 时直接报错，不进行默认资源 fallback。
后端绑定逻辑类型结构保持平台无关，物理 binding 随 Target 保存；所有 Vulkan set/binding 在编译期规范化为相对 Program 根的绝对坐标，不序列化独立 descriptorSets[] 或顶层 backend 对象。
反射转换Slang Reflection 必须先按 8.10A 的规范映射生成 ShaderReflectionIR；binding range、descriptor range 与 sub-object range 是三个不同索引域，不允许按相同下标隐式关联。
BindingPath编译期按 8.10B 保存 VariableLayout 访问链及 ConstantBuffer/ParameterBlock 截止点，计算各类别的累计地址；它是临时算法状态，不写入 SLC2。
接口源码可使用 interface/generic，但产出前必须解析为固定具体类型；运行时不能更换具体类型或生成 specialized Pipeline。
兼容判断pipelineLayoutFingerprint 使用完整 256 位 SHA-256，标识各块默认 Uniform Buffer 与资源 descriptor 规范化后的完整物理 Pipeline Layout；只支持精确相等，不表示代码、名称、逻辑类型图或 Vulkan set 前缀兼容。

8.1 单根反射模型（已确认）

  • rootBlockId 指向当前 ProgramId × TargetKey × Variant 唯一的根 ParameterBlock；它是逻辑 ShaderVar 地址与名称路径的起点，不等同于 Vulkan set = 0，也不表示只会生成一个 descriptor set。
  • Module 全局作用域中的普通数据和资源成为根块成员；显式 ConstantBuffer/ParameterBlock 作为根块之下的子对象，通过父块的 resource range 与 subBlockId 连接到对应子 ParameterBlock。
  • 运行时从根块的零复合偏移开始解析名称并逐层累计；进入 ConstantBuffer/ParameterBlock 子对象时切换到其 subBlockId，再从子块零偏移继续。
  • EntryPoint 的 varying/system-value 输入输出属于 Stage 接口，不进入 ParameterBlock 类型树。当前版本禁止 EntryPoint uniform/resource 参数，因此不需要 EntryPoint 专属 ParameterBlock、第二个反射根或 entryPointBlockId。
  • 同一 Variant 的全部 Stage 引用这一份单根 Layout；Stage Record 只保存阶段身份与目标代码，不拥有可绑定参数根。

8.2 两种地址空间

Layout 在文件结构上是一个整体，但内部必须保留两种不同语义。ShaderVar 地址回答“变量位于哪个 ParameterBlock、类型节点、uniform 字节偏移或 resource range”；Target binding 回答“该 range 在 Vulkan 中对应哪个 descriptor set/binding”。二者不能合并为同一个整数：

语义序列化位置解决的问题

逻辑资源范围types[].resourceRanges[]描述资源种类、数量以及 ParameterBlock 内部扁平存储的 baseIndex。
Target 物理绑定parameterBlocks[].rangeBindings[].descriptorRanges[] 与 defaultUniformBuffer创建 Vulkan DescriptorSetLayout/PipelineLayout，并把逻辑 range 的每个元素更新到一个或多个自动生成的物理 descriptor。

resourceRangeIndex 是 ParameterBlock 的内部范围索引，不是 Vulkan binding。映射身份是 (blockId, rangeIndex)；对应的 rangeBinding 再通过 0～N 条 descriptorRanges[] 或一个 subBlockId 表达当前 Target 的落点。

8.3 ID 化反射图

  • types[] 和 parameterBlocks[] 使用从 0 开始的 Layout 局部整数 ID 引用。SLC2 不序列化 C++ 指针、vtable、slang::TypeLayoutReflection*、运行时 NameId 或后端原生枚举整数。
  • basic 保存标量、向量或矩阵形状、uniformByteSize、矩阵主序和矩阵 stride；struct 保存成员；array 保存元素类型、固定数量和元素 stride；resource 保存资源种类、shape、访问模式、元素类型和可选 image format；parameterBlock 保存 containerKind 并引用其元素类型。
  • 数组类型按聚合类型保存，不为每个元素复制类型或成员记录。运行时路径解析器识别 [index]，按数组节点的元素数量与 stride 计算元素位置，并可把已解析路径惰性缓存为 NameId → ShaderVarLocation。
  • 每个成员保存局部名称、typeId 和相对直接父类型的复合偏移：uniformByte、resourceRange、resourceIndex；不存在的偏移使用 JSON null。禁止保存相对根 ParameterBlock 的绝对偏移。
  • SLC2 不保存独立 names 字段，也不重复保存规范全名。运行时遍历成员局部名称构造完整路径，例如 gMaterial.baseColorTex。
  • NameId 和 NameId → ShaderVarLocation Hash 索引只在运行时加载 Layout 后派生，不进入 SLC2。
  • 短名称只有在 Program 内唯一时才能作为别名；歧义名称必须报错。
  • 同一 Variant 的 VS、PS 等 Stage 必须使用这一份共享 Layout；物理 binding 的 Stage 使用范围记录在对应 descriptorRanges[].stageMask 或 defaultUniformBuffer.stageMask 中。
  • Layout 会随源码、入口组合、Slang 版本、Target 或 Variant 改变，必须随编译单元保存。
  • 不同 Variant 可以产生不同资源集合和自动 binding，禁止跨 Variant 复用布局、派生名称索引或 descriptor set。

8.4 ShaderVar 相对偏移契约（已确认）

"offset": {
  "uniformByte": 16,
  "resourceRange": 2,
  "resourceIndex": 0
}
  • members[].offset 始终相对于成员所在的直接父类型或父容器，不相对于根 ParameterBlock。根 ShaderVar 的三个累计偏移从零开始。
  • uniformByte 是相对父类型普通数据区的字节偏移；resourceRange 是相对父类型 resource-range 列表的范围偏移；resourceIndex 是该范围内的相对元素索引。
  • 三个分量分别累加并且可以独立为 null；同时包含普通数据与资源的 struct 成员可以同时具有有效 uniform 和 resource 分量。
  • 访问嵌套成员时，运行时执行 AccumulatedOffset = ParentOffset + MemberRelativeOffset。因此同一个类型节点可以在多个父位置复用，不需要为每条完整路径复制绝对偏移。
  • 跨越嵌套 ParameterBlock/ConstantBuffer 子对象时，父块的 range binding 用于找到 subBlockId；随后切换到子块，并以子块根零偏移继续成员访问，不把父块内部偏移带入子块。

8.5 Uniform Buffer 存储契约（已确认）

  • 首版的 ordinary/uniform 数据只使用 descriptor-backed Uniform Buffer，不支持 Push Constant。Layout 和 SLC2 均不存在 storage-domain、Push Constant range 或 Push Constant payload。
  • Module 全局作用域中的普通数据归属根块，写入根块的普通数据区，并由根块的 defaultUniformBuffer 提供当前 Target 的物理绑定。
  • 允许 ParameterBlock<T> 的元素类型直接包含普通字段；这些字段由 Slang 聚合到该块自己的默认 Uniform Buffer。显式 ConstantBuffer<T> 作为子块，其普通数据同样归属子块自己的 defaultUniformBuffer。
  • 对每个 parameterBlocks[] 记录，uniformByteSize = 0 当且仅当 defaultUniformBuffer = null；uniformByteSize > 0 时必须存在一条有效物理映射，且 role = "uniformData"。
  • 普通数据的运行时地址是 (blockId, uniformByte)。沿 struct/array 成员访问时逐层累计 uniformByte；跨 subBlockId 后切换到子块并从子块根零偏移重新累计，不需要额外的 storage-domain 字段。
  • 编译器若从 Slang 反射发现 Push Constant binding category、BindingType::PushConstant 或等价布局，必须产生明确诊断并使当前 ProgramId × TargetKey × Variant 编译失败，不得写出部分或降级后的 SLC2。

8.6 数组访问契约（已确认）

  • 运行时提供 ShaderVar[index] 或等价的 operator[](size_t)；名称路径支持成员与数组下标混合，例如 materials[2].baseColorTex、textures[3] 和 clusters[1].lights[7]。items.0 不是合法的数组语法。
  • SLC2 的 array 类型至少保存 elementTypeId、正整数 elementCount、elementByteStride、聚合字节大小和聚合 resourceRanges[]。数组元素共享同一个元素类型节点，不得按元素展开或复制序列化。
  • 普通数据元素的累计位置为 parentUniformByte + index × elementByteStride。资源数组按 nextResourceIndex = currentResourceIndex × elementCount + index 将多维下标按行优先展平，再由当前 blockId 的 rangeBindings[rangeIndex] 映射到物理 descriptor。
  • 固定数组聚合元素类型的 ranges，但不复制类型节点：arrayRange.count = elementRange.count × elementCount，arrayRange.baseIndex = elementRange.baseIndex × elementCount。baseIndex 属于当前类型统一逻辑资源槽空间，不按 SRV/UAV/Sampler 分组，也不参与 Vulkan binding 查找。
  • Vulkan 数组元素更新位置为 dstArrayElement = arrayElementBase + resourceIndex × logicalElementStride；set 与 binding 保持不变，禁止使用 binding + resourceIndex。
  • 固定数组必须执行边界检查；越界、对非数组使用下标、负数或非十进制下标均返回明确诊断。运行时名称索引不预先展开全部数组元素，而是解析规范路径并惰性缓存最终 ShaderVarLocation。
  • 固定资源数组的单元素名称绑定属于首期契约；公共 API 还可增加整段数组赋值以减少逐元素调用。资源数组不再因为“存在数组”而统一编译失败。
  • 当前设计只支持固定长度数组。Slang 反射对任一数组或资源 range 返回 SLANG_UNBOUNDED_SIZE、SLANG_UNKNOWN_SIZE 或等价的非确定数量时，当前编译单元必须失败且不得生成 SLC2。elementCount、逻辑 range 的 count 和物理 descriptorCount 均为正的有限整数；Schema 不保存 unbounded 字段，也不启用 variable descriptor count、partially-bound 或 update-after-bind 容量契约。

8.7 ConstantBuffer/ParameterBlock 数组限制（已确认）

  • 禁止“块本身形成数组”。ConstantBuffer<T> blocks[N]、ParameterBlock<T> blocks[N]、ConstantBuffer<T[N]> 和 ParameterBlock<T[N]> 均编译失败。
  • 若某个数组的元素类型直接包含，或经 struct/array 成员间接包含 ConstantBuffer/ParameterBlock，则该数组会重复块实例，同样编译失败。
  • 不禁止“单个块内部包含数组”。一个非数组的 ConstantBuffer/ParameterBlock 的元素类型可以包含普通数据数组、Texture/Buffer/Sampler 等资源数组及其嵌套数组；它们继续使用 8.6 的通用类型、下标和 range 映射规则。
  • 因此每个父块的子对象映射始终只有一个 subBlockId。Schema 不增加 subBlockIds[]、块实例下标、块 descriptor stride 或 ShaderVarLocation.blockIndex。
  • 序列化器必须验证：parameterBlock.elementTypeId 不能直接指向 array；任一可达 array.elementTypeId 的类型闭包也不能包含 kind = "parameterBlock"。违反任一条件都不能生成有效 SLC2。
// 允许：一个块内部包含普通数据数组和资源数组
struct Data
{
    float values[4];
    Texture2D textures[4];
};
ConstantBuffer<Data> constants;
ParameterBlock<Data> parameters;

// 禁止：块本身或包含块的对象形成数组
ConstantBuffer<Data> constantBlocks[4];

8.9 types[] Type Record 精确契约（已确认）

types[] 是一个以 kind 区分分支的 Tagged Union。每条记录都包含公共字段 id、kind、uniformByteSize 和 resourceRanges[]；其他字段只由对应分支解释。所有枚举均写成 SLC2 自己定义的稳定字符串，禁止写入 Slang、Falcor、Vulkan 或其他后端的原生枚举整数。

公共字段与确定性 ID

TypeRecord
  id                    // Layout 局部 uint32
  kind                  // basic / struct / array / resource / parameterBlock
  uniformByteSize       // 当前 Target 下的 ordinary/uniform 字节数
  resourceRanges[]      // 当前类型直接或聚合包含的逻辑资源 ranges
  • id 从 0 开始连续分配，types[] 必须按 id 升序写入。写入器从 rootBlockId 对应的元素类型开始深度优先遍历，Struct 成员按声明顺序访问，首次遇到某个结构类型时分配 ID；全部类型都必须从根块沿成员和子块关系可达。
  • 类型去重使用完整的规范化 Type Record 结构，不使用 C++/Slang 指针身份。非空 Struct 名称不同的类型不得互相去重；匿名 Struct 可以按完整成员结构去重。
  • uniformByteSize 只统计 ordinary/uniform 数据，不统计 Texture、Buffer、Sampler 或其他 descriptor。资源容器自身为 0，其元素普通数据由对应 parameterBlocks[].uniformByteSize 保存。
  • ID、字节大小、stride 和 offset 都是非负 JSON 整数，读取时必须执行 uint32 范围检查；数组 elementCount、resourceRanges[].count 和物理 descriptorCount 还必须大于 0。Slang 对 ordinary data、数组或资源 range 返回 unknown/unbounded size 时，该编译单元失败，不能写入有效 SLC2。
  • 不序列化通用 alignment 或通用 stride；已保存的成员相对偏移、块大小、数组元素 stride 和矩阵 stride 足以完成运行时寻址。

8.10 resourceRanges → rangeBindings 精确映射（已确认）

  • parameterBlocks[].elementTypeId 指向块内容的根类型；rootBlockId 指向 Program 唯一的根 ParameterBlock。其他 ParameterBlock 只能作为由根块可达的 ConstantBuffer/ParameterBlock 子对象，不存在独立的 EntryPoint 根块。
  • uniformByteSize 描述块的普通数据区；其与 defaultUniformBuffer 的空值关系和物理绑定要求严格遵守 8.5。
  • 设 N = types[elementTypeId].resourceRanges.length，则当前块必须有恰好 N 条 rangeBindings[]。这里的 Type 和 logical ranges 均是当前 Program × Target × Variant 裁剪后的 IR，不是 Slang 原始 binding range 的镜像；其中 rangeIndex 唯一、完整覆盖 [0, N)，写入器按升序输出，读取器按显式字段匹配。
  • rangeIndex 的作用域是当前 blockId，所以完整身份是 (blockId, rangeIndex)。resourceRanges[] 的数组顺序具有语义；成员的相对 resourceRange 偏移和 rangeBindings[].rangeIndex 都引用该顺序。
  • flavor = "simple" 时，subBlockId 必须为 null，并保存 1～N 条 descriptorRanges[]。Schema 保留“一条逻辑 range 降低为多个物理 descriptor”的能力，禁止把两个索引域写死为一一对应；当前不支持的 CombinedTextureSampler 仍按 8.10A 明确失败。
  • 每条 Vulkan descriptor mapping 保存稳定字符串 role、绝对 set/binding、arrayElementBase、logicalElementStride、descriptorType、具体 descriptorCount、合并后的 stageMask 和 flags。运行时对每条 mapping 执行 dstArrayElement = arrayElementBase + resourceIndex × logicalElementStride。
  • flavor = "constantBuffer" 或 "parameterBlock" 时，descriptorRanges[] 必须为空，subBlockId 必须指向有效且从根可达的子块。子块自己的 default uniform buffer 和资源 mapping 拥有物理 descriptor，父块不得重复写入 Slang 向父作用域暴露的 descriptor range。
  • 所有块内的 Vulkan set/binding 都在编译期规范化为相对 Program 根的绝对 Target 坐标。块图必须无环；一个非根块只能由一个子对象出现位置拥有，避免同一物理 descriptor 出现多个写入所有者。
  • Slang 的每个 binding range 都生成独立逻辑 range，包括显式 UAV counter 等无用户名称的辅助 range。辅助 range 使用 internalRole/ownerRangeOffset，主资源类型使用 auxiliaryRanges[]；一次按名称绑定必须自动更新主 range 和全部辅助 range。
  • Schema 2 的每条 simple descriptor mapping 固定满足 arrayElementBase = 0、logicalElementStride = 1、descriptorCount = logical range.count；这三个字段不是自由配置。若某个 Slang Target 产生非恒等逻辑元素映射，当前编译单元失败，必须先提升 Schema 并定义新寻址规则。
  • ConstantBuffer/ParameterBlock 数组是已确认的禁止形态；当前 Schema 不为其定义块实例索引或物理 descriptor stride，也不存在自动启用该形态的隐含契约。单块内部 Texture、Buffer、Sampler 和 ordinary 数据数组不受此限制。

聚合 logical range 的规范化

resourceRanges[] 不应对每种 Type Kind 都独立猜测辅助关系。Builder 先建立叶类型 range，再按类型图向上聚合，并用当前 TypeLayout 的 Slang range 查询逐项复核：

Resource 或 ParameterBlock 叶类型:
  直接读取本类型 binding ranges
  baseIndex = 前序 range.count 的 checked 前缀和
  显式 counter 建立 internalRole/ownerRangeOffset

Struct:
  按成员声明顺序拼接成员类型的规范化 ranges
  memberStart = parent.getFieldBindingRangeOffset(memberIndex)
  对成员 counter:
    parent.ownerRangeOffset =
      memberStart + child.ownerRangeOffset
  重新计算 parent baseIndex 前缀和

Array:
  range 顺序与元素类型一致
  array.count = child.count × elementCount
  array.ownerRangeOffset = child.ownerRangeOffset
  重新计算 array baseIndex 前缀和

最终逐项验证:
  normalized.length == typeLayout.getBindingRangeCount()
  normalized[i].count ==
    typeLayout.getBindingRangeBindingCount(i)
  normalized[i].resourceKind 与
    getBindingRangeType/getBindingRangeLeafTypeLayout 一致

因此同一显式 counter 在 Resource、外层 Struct 和外层 Array 的 Type Record 中都指向各自局部 range 数组里的主 range。baseIndex 只表示当前类型的扁平逻辑资源槽前缀，不从 Slang 的 set/binding 推导。

  • ShaderDescriptorRole 的稳定集合为 primary、sampler、counter、uniformData。默认 Uniform Buffer 固定为 uniformData；internalRole = "counter" 的逻辑 range 固定为 counter；非 Sampler 逻辑 range 若存在独立 Sampler descriptor 使用 sampler；其余 mapping 使用 primary。
  • 独立 Sampler 资源自身的物理 descriptor 使用 primary，不是 sampler；后者只表示同一逻辑主资源的辅助 Sampler 角色。每个 simple range 至少有一个 primary，或在该 range 为内部 counter 时恰好使用 counter；同一 range 内 (role, set, binding) 不得重复。

8.10B BindingPath 完整契约

BindingPath 是 Slang 官方 access-path 累加算法在 Builder 内的强类型实现，用于把 VariableLayout 的直接父相对 offset 转成当前 Target 的绝对物理地址。它只在 linked component 与 ProgramLayout 有效期间存在，不进入 IR、SLC2 或运行时对象。

名称生命周期职责
Builder BindingPath仅一次 SlangReflectionBuilder::Build()累加 Slang VariableLayout 的相对 category offset；不含资源名称和运行时数组下标。
IR 成员图路径SLC2/运行时由 types[].members[]、Array Type Record 与 subBlockId 表达；不是一条序列化字符串。
运行时资源名称路径加载后的 Program/Variant由 IR 图派生，例如 material.albedo；解析为 ShaderVarLocation，与 Builder BindingPath 无共享对象。
 
BindingPathNode

  outer                     // 外层节点；根节点 outer = null

  • 链方向：leaf → outer → … → root。Append(path, varLayout) 只在叶端增加节点，并原样继承两个 deepest 标记。所有节点由单次 Builder 的 arena 持有，不能保存 Slang 指针到 Build 返回之后。
  • 结构不变量：leaf 可空；两个 deepest 指针必须为空或属于同一条 leaf 链。两者同时存在时，沿 leaf → root 必须先遇到或同时遇到 deepestConstantBuffer，再遇到 deepestParameterBlock。禁止把不同 Builder arena 的节点拼接为同一路径。
  • 根：空路径追加 ProgramLayout::getGlobalParamsVarLayout() 得到根 occurrence path。必须保留该根 VariableLayout 的 offset；不得假设全局 scope 永远从 set/binding 0 开始。
  • Struct：进入字段时把 getFieldByIndex(i) 返回的字段 VariableLayout 追加到当前路径；字段 offset 始终相对直接父 Struct。
  • 聚合 descriptor：当 Builder 在某个块的元素 TypeLayout 上枚举 descriptor ranges 时，Slang 的 descriptor set/range 局部 offset 已经汇总该 TypeLayout 内部的 Struct/Array 路径，因此 ownerBindingPath 只到该块 elementPath，不能再追加 getBindingRangeLeafVariable()。只有逐变量累计或进入块子对象时才扩展路径。
  • 数组：BindingPath 只定位数组变量整体，不为某个元素创建伪 VariableLayout，也不把运行时下标写进路径。递归构建数组元素的 canonical Type Record 时使用独立的 type-only 上下文，不沿用 occurrence BindingPath；数组的普通数据 stride、逻辑 range 聚合和资源下标展平由 Type Record 保存并在运行时计算。
  • 进入单元素容器：设 blockOccurrencePath 的 leaf 是当前 ConstantBuffer/ParameterBlock 出现位置。复制为 innerBase，令 deepestConstantBuffer = blockOccurrencePath.leaf；若 getContainerVarLayout()->getTypeLayout()->getSize(SubElementRegisterSpace) > 0，再令 deepestParameterBlock = blockOccurrencePath.leaf。随后分别生成 containerPath = Append(innerBase, getContainerVarLayout()) 与 elementPath = Append(innerBase, getElementVarLayout())。
  • 子对象：仅对 ConstantBuffer/ParameterBlock 使用 subOccurrencePath = Append(currentElementPath, getSubObjectRangeOffset(s))，再按上一条进入其 leaf 容器。getSubObjectRangeSpaceOffset(s) 必须是有限值，但不是另一份 BindingPath offset，不能与 offset VariableLayout 重复相加。StructuredBuffer 的 sub-object range 是 Slang shader-object 存储信息；在拒绝动态 specialization 后，它只用于结构校验，不生成引擎子块。
  • 静态 specialization：路径只有这一条主链，不存在 Falcor 的 deferred/pending path。当前版本在反射前已经完成静态 specialization，且不调用已废弃的 getPendingDataLayout()。

类别累计公式

Resolve(Uniform, path):
  result = { value = 0, space = 0 }
  for node = path.leaf;
      node != path.deepestConstantBuffer;
      node = node.outer:
    result.value += node.varLayout.getOffset(Uniform)
  return result

Resolve(category, path):
  require category in {
    ConstantBuffer, ShaderResource, UnorderedAccess,
    SamplerState, DescriptorTableSlot
  }
  result = { value = 0, space = 0 }
  for node = path.leaf;
      node != path.deepestParameterBlock;
      node = node.outer:
    result.value += node.varLayout.getOffset(category)
    result.space += node.varLayout.getBindingSpace(category)
  for node = path.deepestParameterBlock;
      node != null;
      node = node.outer:
    result.space +=
      node.varLayout.getOffset(SubElementRegisterSpace)
  return result
  • 循环截止节点是不包含边界：Uniform 不把最深 ConstantBuffer 出现位置及其外层字节 offset 带入子块；descriptor 类别不把最深 ParameterBlock 之前的局部 binding 带入新 space，但通过第二个循环保留 ParameterBlock 的绝对 space。
  • 每次读取 getOffset/getBindingSpace/getDescriptorSet* 的结果都先拒绝负数、unknown/unbounded，再使用 checked uint64 加法；最终写 IR 前 checked narrow 为 uint32。空链、边界节点不属于当前链、链提前结束、任一溢出都属于 Builder 内部/输入布局错误。
  • 当前 Vulkan 后端只接受 descriptor range category 为 DescriptorTableSlot。其他 space-aware 类别保留在通用解析器中，供 Stage 使用查询及未来 Target adapter 使用；不得把不同类别的 offset 混加。

8.11 pipelineLayoutFingerprint 规范编码与 Hash（已确认）

pipelineLayoutFingerprint 是当前 ProgramId × TargetKey × Variant 的完整物理 Pipeline Layout 身份。它只回答两份布局能否作为“完全相同的物理布局”候选复用，不标识 Shader 代码、名称、逻辑反射树，也不表达 Vulkan descriptor set 前缀兼容。

SOLAR-PIPELINE-LAYOUT/v1
backend=vulkan
pipelineFlags=-
setCount=1
set=0;flags=-
binding=0;type=sampledImage;count=1;stages=compute;flags=-
  • 输入收集：从 rootBlockId 遍历全部可达 ParameterBlock，收集所有非空 defaultUniformBuffer 与全部 rangeBindings[].descriptorRanges[]。默认 Uniform Buffer 先归一化为普通物理 descriptor 记录，再与资源 descriptor 一起处理。
  • 合并与冲突：按绝对 (set, binding) 分组。只有 descriptorType、有限 descriptorCount、binding flags 以及 immutable sampler 状态完全一致的重复记录才能合并，合并时取 Stage mask 并集；任一字段冲突均为编译错误。当前版本不支持 immutable sampler，其状态固定为“无”。
  • 确定性排序：set 与 binding 按无符号数值升序。setCount = maxSet + 1，中间空 set 仍占索引并写出 set 记录；完全没有 descriptor 时 setCount = 0。v1 Stage 固定顺序为 vertex, hull, domain, geometry, fragment, compute，flags 使用稳定字符串升序；未来新增 Stage 必须提升规范版本并规定新顺序，禁止依赖反射遍历、JSON 对象或容器迭代顺序。
  • 规范文本：首行是域与编码版本；随后写 backend、Pipeline flags、setCount、各 set 的派生 flags 和各 binding 的 type/count/stages/flags。枚举使用 SLC2 定义的稳定小写字符串；整数使用无前导零十进制；空集合写 -。文本编码固定为无 BOM UTF-8、LF 换行，并包含最后一个 LF。
  • 当前字段边界：规范输入包含域/版本、backend、Pipeline flags、setCount、派生 set flags、binding、descriptorType、有限 descriptorCount、stageMask 和 binding flags。v1 的 Pipeline/set flags 均为 -；Target meta 不保存 optimize/debug 等编译选项，它们由统一编译策略固定且不是 Pipeline flags。当前未增加独立 descriptorSets[]。未来若引入非空 Pipeline/set flags、immutable sampler 或 Push Constant，必须先扩展稳定描述并提升规范编码版本。
  • 明确排除：ProgramId、Variant、EntryPoint、Stage 代码及其 hash、成员和资源名称、type/block/range ID、逻辑 resourceKind/shape/format、uniform 大小与偏移、arrayElementBase、logicalElementStride、role、默认资源和当前绑定资源均不进入输入。这些字段影响代码、名称寻址或 descriptor 更新，但不改变完整物理 Pipeline Layout 定义。
  • Hash：pipelineLayoutFingerprint = LowerHex(SHA-256(UTF8(CanonicalPipelineLayoutText)))。结果必须是恰好 64 个小写十六进制字符；禁止对格式化 JSON 或平台原生结构体内存直接求 hash。上例的结果是 5bb34bc5c853d1ac8ea025d063249a99e90331d055a875fce50642578c04c899。
  • 加载校验与复用：读取器必须从 SLC2 的物理记录重新生成规范文本并校验 fingerprint；不一致即缓存无效。运行时 Pipeline Layout 缓存命中同一 hash 后，还必须深比较规范化物理记录，确认完全相等后才复用 GPU 对象。
  • 兼容范围：v1 只定义完整 Pipeline Layout 精确相等，不实现 Vulkan set-prefix compatibility 优化。未来如需按 set 或前缀复用，可在运行时从同一规范记录派生独立 fingerprint；它们不进入当前 SLC2 Schema。

8.12 Interface 静态 Specialization 边界（已确认）

  • 不实现 Falcor/Slang-gfx 式运行时 interface specialization。运行时不得根据当前绑定的 Shader Object 具体类型收集 specialization arguments，不调用 Slang specialize()，也不生成新的 Shader、Layout 或 Pipeline。
  • Slang interface、generic 和 type conformance 可以用于源码组织，但在提取目标代码和 ShaderReflectionIR 前必须已经解析为固定具体类型；仍包含未解析 existential/interface specialization 参数的 linked component 编译失败。
  • 运行时可以修改具体对象中的 Texture、Buffer、Sampler 和 uniform 数据，但不能把同一个接口槽位从一种具体类型切换成另一种具体类型。
  • SLC2 v2 首期不增加 SpecializationKey 或 specializations[] 层级，只保存已经完全静态 specialization 的代码与 Layout。若未来需要同一 Program 的多个离线类型组合，必须作为独立的编译期缓存维度另行设计，不能隐式退化为运行时编译。
  • 运行时不携带 Slang compiler、未 specialization 的 Slang ComponentType 或用于即时 specialization 的 Module IR。

8.13 资源绑定完整性与缺失错误（已确认）

  • 系统中不定义 required/optional 资源语义。Shader 源码不使用 Attribute、宏或其他声明标记资源是否必须绑定；编译器不分析或推断这种策略，运行时 API 也不要求调用者配置绑定策略。
  • 每个运行时资源槽保存一个可为 null 的显式资源值。设置非空资源表示绑定该槽位；从未设置或设置 null 都表示该槽位当前未绑定，不触发任何缺省资源解析。
  • 提交 backend descriptor 前，运行时必须验证当前 ParameterBlock 中所有需要写入 descriptor 的资源槽。任一槽位未绑定或资源类型不兼容时，立即返回包含完整资源路径、期望资源类型及 (blockId, rangeIndex, resourceIndex) 的绑定错误，中止 descriptor 更新以及对应的 Draw/Dispatch。
  • 固定资源数组按元素执行完整性校验；每个元素都必须显式绑定类型兼容的非空资源，缺少任一元素均使本次提交失败。所有数组槽位数量在编译期确定；当前设计不存在无界 range 或运行时容量配置。
  • SLC2 不保存 bindingRequirement、required、optional、默认资源标识或 fallback 策略。ShaderReflectionIR 只保存名称路径所需的类型结构、资源类型与逻辑/物理绑定映射；统一的运行时绑定完整性校验不改变 Layout、Variant 或 pipelineLayoutFingerprint。
  • 当前阶段不实现默认资源库。运行时不得为未绑定槽位自动创建、选择或填充 Texture、Buffer、Sampler 或其他替代资源。

10. 运行时读取、Variant 匹配与绑定

  1. 规范化 Shader Resource Path，计算 SHA-256 并定位唯一 SLC2 文件。
  2. 解析 JSON，验证文件名、Magic、Major 版本、必选字段、字段类型和基本结构。
  3. 使用调用者传入的区分大小写 ProgramId 字符串，在 programs[] 中做完全匹配并选择 Program。
  4. 从 meta 生成 TargetKey，按调用者请求的 Platform × Backend × ShaderModel 完全匹配唯一 Target。API/目标二进制版本和 capability 基线由当前引擎的统一编译策略保证，不作为 SLC2 内的第二套可变匹配维度。
  5. 使用 Program 的 variantGroups 对运行时宏集合执行 NormalizeVariant。
  6. 在 Target 的 variants[] 中按规范化字符串完全匹配并选择唯一 Variant。
  7. 验证共享 Layout 的 schema = 2、ID 引用、类型图、ParameterBlock、(blockId, rangeIndex) 完整映射、descriptor/subBlock 互斥关系、固定有限数量、物理 binding 唯一所有权、StageRecordKey 唯一性和阶段集合完整性；按 8.11 重建规范物理布局并重算 pipelineLayoutFingerprint，再按需解码各 Stage 代码并校验长度和 SHA-256。
  8. 先从 types[] 和 parameterBlocks[] 重建单根不可变运行时反射对象，再从 rootBlockId 沿成员局部名称与子块连接派生完整路径并建立 NameId → ShaderVarLocation 索引；不得为 Stage 创建额外参数根。
  9. 从 rootBlockId 遍历全部可达块，收集非空 defaultUniformBuffer 和 rangeBindings[].descriptorRanges[]，按绝对 (set, binding) 分组创建 Vulkan DescriptorSetLayout/PipelineLayout；SLC2 不提供独立 descriptorSets[]，也不创建 Push Constant range。
  10. 每次 CreateProgramInstance() 都从 rootBlockId 递归创建独立 ShaderParameterBlock 树：每个 blockId 初始化自己的 CPU 普通数据区、逻辑资源槽和由 block-flavor mapping 指向的唯一子块。ShaderProgramReflection、后端布局和 Stage GPU 对象继续共享。
  11. 按名称或由根 ShaderVar 访问成员时，先得到 ShaderVarLocation，再绑定到对应运行时 ParameterBlock。写入普通数据时，以该 blockId 的 CPU 普通数据区和累计 uniformByte 定位成员；写入资源时，以 (blockId, rangeIndex, resourceIndex) 定位可空显式资源槽。设置 null 后该槽位处于未绑定状态。
  12. 提交前 ValidateAllBindings() 执行两阶段遍历：第一阶段验证全部可达块的 simple logical range、每个固定数组元素和资源类型，并把逻辑资源复制到待冻结快照；第二阶段才物化所有非空 defaultUniformBuffer 对应的 GPU Buffer 并加入快照。任一失败都不产生快照、不写 descriptor，并中止对应 Draw/Dispatch。
  13. 只有冻结的 ShaderBindingSnapshot 可交给 Descriptor Writer。Writer 对每条 descriptor mapping 计算 dstArrayElement = arrayElementBase + resourceIndex × logicalElementStride 并只写入快照中的显式资源；该过程不读取 required/optional 策略，也不执行默认资源 fallback。
