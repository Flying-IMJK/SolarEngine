# 前置条件与工程边界

目标：Shader 编译系统基于 SolarEngine 现有工程结构实现。Slang 已由 SolarEngine 接入，本设计不负责 Slang 的工程接入、构建、部署或版本管理。

## Slang 前置条件

SolarEngine 已提供可直接使用的 Slang 编译 API：

- 编译实现可以直接 `#include <slang.h>`。
- 编译实现可以直接 `#include <slang-com-ptr.h>`。
- Slang 头文件、库和运行所需动态库由 SolarEngine 工程保证可用。
- 当前设计不新增 Slang clone、build、install、copy、link 或 dependency 脚本。

已确认的工程位置：

```text
SolarEngine/Src/Libraries/slang
  include/
  bin/
  link.cmake
  README.md
  LICENSE
```

`CompilerBuildTag` 仍需要包含能够使缓存失效的编译器身份信息，但其 Slang 部分来自 SolarEngine 已接入的 Slang 编译器标识，而不是本设计单独指定的 Slang 来源版本：

- SolarEngine Shader 编译器修订。
- SolarEngine 当前可用的 Slang 编译器标识。
- SLC2 schema。
- Target 策略版本。

## 引擎基础设施优先原则

Shader 编译系统的实现默认使用 SolarEngine 已有基础设施，不直接绕过引擎平台层：

- 路径规范化、合并、相对路径消解、文件/目录存在性判断使用 `FileSystem`。
- 文件读取/写入使用 `File`。
- 文本与第三方 `const char*` 边界使用 `String` / `StringAnsi` / `StringView`；第三方 API 需要 `const char*` 时，以 `StringAnsi` 持有桥接对象生命周期。
- 动态数组、字节缓冲和集合优先使用 `List` / `DataContainer` / 引擎集合。
- Hash、Base64、JSON、日志、断言、线程与原子操作优先使用引擎提供的方法。
- STL 只允许作为第三方 ABI 无法避免的局部桥接或引擎尚无等价能力时使用；不得作为路径语义、文件 IO、持久化格式、日志、线程、内存生命周期的默认实现。
- 控制流分支必须显式使用 `{}`，包括单语句 `if` / `else` / `for` / `while`；新增 Shader 编译路径不允许无括号当行分支。

## SolarEngine 模块落点

| 模块 / 目录 | 新路径职责 | Slang 依赖 |
| --- | --- | --- |
| `Src/Engine/Runtime/ShaderCompilation` | Slang 编译入口、请求/结果、Program 发现、Variant、Target、IR、SLC2 | 编译侧可直接使用 |
| `Src/Engine/Runtime/ShaderCompilation/Vulkan` | 旧 glslang Vulkan 编译路径保留给旧入口，新 Slang 路径不依赖其反射结果 | 新路径不通过这里做反射 |
| `Src/Engine/Runtime/ShaderCompilation/Parser` | 旧 `.shader` / HLSL Parser，Slang-only 新入口完全绕过 | 否 |
| `Src/Engine/Runtime/GraphicsDevice/Vulkan` | 运行时从 SLC2/IR 创建 Vulkan Layout、ShaderModule、Descriptor 写入 | 否 |
| `Src/Engine/Shaders` | 现有旧 Shader 资源目录；新 Slang 资产后续按 SolarEngine 资源规则接入 | 编译时使用 |

## 公开入口边界

现有入口：

```cpp
namespace SE
{
    class ShadersCompilation
    {
    public:
        static bool Compile(ShaderCompilationOptions& options);
    };
}
```

新路径不复用旧 `ShaderCompilationOptions` 的语义作为完整设计输入，而是新增 Slang-only 请求/结果结构，并由 `SE::ShadersCompilation` 暴露新入口或新调度分支。

旧入口继续服务旧资产；新入口只接受 Slang Shader 资产，不做语言嗅探和自动 fallback。

## 编译侧可以做

- 创建 `slang::IGlobalSession`。
- 每次请求创建独立 `slang::ISession`。
- 加载根 Module。
- 读取 Program marker Attribute。
- 调用 `findAndCheckEntryPoint`。
- 链接 `IComponentType`。
- 读取 `ProgramLayout`。
- 生成 `ShaderReflectionIR`。
- 写入并 self-read SLC2。

## 运行时侧不能做

- `#include <slang.h>`。
- 链接或调用 Slang。
- 保存 Slang 反射指针。
- 从 SPIR-V 二次反射来补充布局。
- 参与 Program 发现、Variant 规划、Target codegen 或 SLC2 写入。

## Slang 生命周期

```text
Process:
  IGlobalSession

Compile request:
  ISession
    target desc
    preprocessor macros
    SlangShaderFileSystem
```

规则：

- `IGlobalSession` 由编译服务进程级持有。
- 每次编译请求创建独立 `ISession`。
- `ShaderCompileRequest` 不携带 `SearchPaths`；根文件目录、import/include 查找和未来引擎虚拟路径映射均由编译侧 `SlangShaderFileSystem` 负责。
- `SlangShaderFileSystem` 的路径操作和文件读取必须走 `FileSystem` / `File`；不得使用 `std::filesystem`、`std::ifstream` 或调用方传入 search path。
- Slang COM 对象使用 `Slang::ComPtr`。
- 不把裸反射指针保存到请求之外。
- `ProgramLayout` 生命周期不超过 linked component；运行时数据必须提前复制进 IR。

## 接入验收

- 编译侧源码可直接 include Slang 公共头。
- 新 Slang 编译入口不调用旧 Parser。
- 新 Slang 编译入口不调用旧 `RequestCompiler(ShaderProfile)`。
- 编译侧可以在没有 GPU 设备和 Vulkan runtime 的情况下完成 Compile-only 闭环。
- 运行时模块不依赖 Slang 头文件或 Slang 反射对象。
- 已生成 SLC2 可由无后端 `SLC2Reader` 读取和校验。
