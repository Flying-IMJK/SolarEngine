Shader 编译系统实现阶段、测试与退出条件 · v2

测试与交付 v2

每个阶段都形成可验证的纵向切片，失败时能定位在接口、编译、IR、缓存或 Vulkan 层。

1. 交付策略

实施采用“先建立可独立运行的编译闭环，再接入运行时名称解析，最后打通 Vulkan Compute 和 Graphics”的依赖顺序。依赖图允许的阶段可以并行开发，但下游只能消费已满足退出条件的上游接口；不得在 Vulkan 调试期间同时修改 Variant 规范或 SLC2 schema。

Compile-only 闭环： Slang 源码 → Program/Variant 发现 → Target 编译计划 → linked component → SPIR-V + ShaderReflectionIR → SLC2 → 严格 Reader/Validator → 语义 manifest 与字节确定性。
运行时/GPU 闭环： 已存在 SLC2 → Program/Target/Variant 选择 → runtime reflection → 名称绑定 Texture/Buffer/Sampler → Vulkan shared PipelineLayout → Descriptor 写入 → Dispatch/Draw。

提交边界

  • 第三方 Slang 依赖固定与许可证单独提交。
  • 共享数据类型、纯算法与测试先于调用点提交。
  • 编译器、SLC2、runtime reflection、Vulkan adapter 分开提交，但每个合入点保持主分支可构建。
  • 旧调用点的移除独立于新路径功能提交，便于确认不是 Legacy 行为掩盖测试成功。
  • 不在本轮提交 Cook/发布、DependencyIndex、默认资源或 runtime lifecycle 优化。

2. 实施阶段与退出条件

P0 · 依赖与骨架 Slang 已由 SolarEngine 接入；新增公共请求/结果和稳定枚举；建立 API 编译/链接探针与空编译服务。
退出：Slang API probe 编译并链接；GlobalSession + 最小反射 smoke test 通过；runtime 链接依赖不含 Slang。
P1 · 最小 Compute 编译 无资源、无 Variant 的单 CS Program，联合 component、SPIR-V code 与最小 SLC2。
退出：无需 GPU 即可通过 SLC2 Reader/Validator；两次编译字节一致；SPIR-V 通过基础格式与 hash 校验。
P2 · Program 与 Variant marker Attribute 发现、Stage 校验、显式过滤、全量笛卡尔积、TargetKey。
退出：正负 fixture 全通过；空宏 Variant 与必选默认项正确。
P3 · Reflection IR 与 SLC2 完整 types/blocks/range mapping、Writer/Reader/self-read、fingerprint。
退出：所有 schema invariant 可由 mutation test 捕获；compile-only fixture 可输出语义 manifest；runtime 无 Slang。
P4 · Runtime Reflection 与名称绑定 从已存在 SLC2 重建 Program/Target/Variant、ShaderVar、名称解析、逻辑资源状态和提交前完整性验证。
退出：不创建 GPU 对象即可按名称解析 Texture/Buffer/Sampler、固定数组和子块路径；缺失资源可确定性阻止提交。
P5 · Vulkan Compute 绑定闭环 共享 Layout、VkShaderModule、descriptor set layout、descriptor write 和 Compute Dispatch。
退出：validation layer 无错；缺失资源在任何 descriptor update/dispatch 前失败。
P6 · Graphics Program VS/PS 联合链接，可选 HS/DS/GS；单一 Pipeline Layout 与根参数状态。
退出：VS/PS 共享资源只产生一个合并 binding；Draw 正确。
P7 · 完整已设计能力 ordinary uniform 字段、显式 ConstantBuffer/ParameterBlock、UAV、嵌套 struct/数组和辅助 counter。
退出：所有已支持 Type/Range 分支均有 GPU 功能测试和负向边界测试。
P8 · 调用点迁移与清理 新 Slang Shader 资产全面使用新入口；移除新调用链对旧 parser/cache/stage descriptor info 的依赖。
退出：新资产路径不存在 Legacy dispatch；旧资产不被自动迁移或伪装成功。

RunShaderCompileFixture(fixture):
    request = BuildRequest(
        resourcePath = fixture.VirtualPath,
        source = ReadUtf8(fixture.SourceFile),
        targets = fixture.Targets,
        selections = fixture.VariantSelections)

    ShadersCompilation.Compile(request, result)

    IF fixture.ExpectedStatus == Failed:
        CHECK(result.Status == Failed)
        CHECK(result.SLC2Data.IsEmpty)
        FOR text IN fixture.RequiredDiagnostics:
            CHECK(result.CompileMessage.Contains(text))
        return

    REQUIRE(result.Status == Success)
    artifact = REQUIRE_SUCCESS(
        SLC2Reader.ReadAndValidate(result.SLC2Data))
    CHECK(ExtractSemanticManifest(artifact) ==
          fixture.ExpectedSemanticManifest)

    // 同一固定工具链下验证确定性。
    ShadersCompilation.Compile(request, second)
    REQUIRE(second.Status == Success)
    CHECK(second.SLC2Data == result.SLC2Data)

ExpectedSemanticManifest 比较 Program/Target/Variant/Stage、IR 和关键 mapping，不把整段 SPIR-V 文本作为跨 Slang 版本的永久 golden。

5. Golden 与 Mutation 策略

不把易漂移的代码 blob 当唯一真值

  • SLC2 schema golden 只保存小型、手写且含有效完整 SPIR-V 的文件。
  • Slang codegen 回归主要验证成功、Stage、入口、非空代码、SPIR-V 基础结构和同版本确定性，不要求不同 Slang commit 产生相同二进制。
  • Reflection golden 比较稳定 IR 语义，不比较 Slang 原生枚举或指针。
  • SolarEngine 更新内置 Slang 时，先运行语义 diff；只有确认变化符合 Target 策略才更新 golden 和 CompilerBuildTag。

Reader Mutation

对一份有效 SLC2 逐次只修改一个字段：magic/major、重复 ProgramId、Target 枚举、variant、typeId、blockId、elementCount、rangeIndex、descriptorCount、code hash、fingerprint。每个 mutation 必须在 Reader 阶段失败，并验证错误路径。

RunMutationCases(validBytes, cases):
    REQUIRE_SUCCESS(SLC2Reader.ReadAndValidate(validBytes))
    validJson = ParseTestJson(validBytes)

    FOR case IN cases:
        mutated = DeepClone(validJson)
        case.ApplySingleMutation(mutated)
        mutatedBytes = SerializeTestJson(mutated)

        error = REQUIRE_FAILURE(
            SLC2Reader.ReadAndValidate(mutatedBytes))
        CHECK(error.Path == case.ExpectedJsonPath)
        CHECK(error.Message.Contains(case.ExpectedReason))

6. 合入门禁

  1. Build：Windows x64 Editor + Vulkan 编译器模块干净构建；Linux x64 至少编译公共/编译模块；两端 Slang API probe 均使用各自同源头库编译并链接。
  2. Unit：Variant、IR Validator、SLC2、NameResolver、Fingerprint 全通过。
  3. Compile-only：P0-P3 不创建 GPU 设备、不创建 ShaderProgramInstance，也能从请求得到完整 SLC2，通过 self-read、语义 manifest、mutation 和 byte determinism 验收。
  4. Integration：正向/负向 Slang fixture 全通过，失败结果没有部分 SLC2。
  5. Determinism：相同输入连续两次输出 byte-for-byte 相等。
  6. GPU：Compute 主闭环与 Graphics 阶段对应测试通过。
  7. Validation：Vulkan validation layer 无 descriptor/pipeline layout 问题。
  8. Dependency audit：runtime 无 Slang 链接；正式 ThirdParty 与编译进程依赖目录不含 Slang 产品工具、Falcor 或无关产物。
  9. Legacy audit：新资产调用图中没有 Parser::Process、RequestCompiler(profile)、AddBindingsForStage 或 SPIR-V 二次反射。

7. 风险与缓解

风险早期信号缓解
Slang reflection API 名称、签名或语义误读API probe 编译/链接失败，或最小 fixture 的名称、Attribute、入口、binding range 断言失败。SolarEngine 当前接入 Slang 的 API probe、独立 Builder adapter、最小 fixture 和精确 mapping invariant；不提供伪兼容别名，也不在后端猜测。
Stage 独立布局残留VS/PS 为同一资源生成不同 set。只从联合 linked component 构建 IR；Vulkan 新路径禁用 AddBindingsForStage。
Variant 爆炸笛卡尔积溢出或编译时间不可控。生成前 checked multiply 和明确上限；支持显式 VariantSelections。
SLC2 不确定相同输入出现无语义 diff。固定排序/字段顺序，排除路径时间和指针，加入 byte determinism gate。
Slang 升级破坏 ABI/布局加载失败或 IR golden 变化。SolarEngine 内置 Slang 标识、头库同源、升级单独审查并提升 CompilerBuildTag。
缺失资源到 Vulkan 才崩溃空 image/buffer info。逻辑绑定完整性先于任何 descriptor write。
过渡期误用旧入口新 Shader 仍生成 GPU cache v13。显式资产入口、调用图测试和 Legacy audit，不做内容嗅探。

8. 系统完成定义

当 P0～P8 的适用退出条件全部满足时，当前范围内的“替换”完成：

  • 新 Slang Shader 资产只调用新请求/结果 API，旧 HLSL parser 和旧二进制 cache 不在其调用链。
  • Vulkan Compute 与 Graphics 都以完整 Program Variant 的共享 Layout 工作。
  • 运行时按名称与固定数组下标绑定资源，不依赖显式 set/binding、Slang 或 SPIR-V 二次反射。
  • 缺失资源、非法缓存、非法 Variant 和不支持反射结构都产生确定性错误。
  • Cook/发布、DependencyIndex、默认资源、运行时生命周期优化和其他后端仍明确留在后续设计，不以临时实现冒充完成。
