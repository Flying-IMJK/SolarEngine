Shader 编译系统实现名称绑定与 Vulkan 后端 · v2

运行时与 Vulkan v2

从 Program/Target/Variant 选择，到名称解析、资源校验、统一 Pipeline Layout 和 descriptor 写入。

1. 运行时对象与接入边界

系统设计中的“Shader Program”是完整的 graphics/compute 程序，而 SolarEngine 现有 GPUShaderProgram 表示单个 Stage。实施中保留现有 Stage GPU 对象，但新增一个拥有共享 Layout 与参数状态的完整程序对象，避免名称混淆。

边界：运行时从一份已经通过编译侧 self-read 的 SLC2 开始工作，只消费 SLC2GPUShader、ShaderReflectionIR 和 Stage code。运行时不得调用 Slang、不得从 SPIR-V 二次反射，也不得参与 Program 发现、Variant 规划、Target codegen 或 SLC2 写入。

与现有 GPUShader 的过渡

  • 为新 Slang Shader 资产增加明确的 SLC2 加载入口；不通过文件内容嗅探在旧二进制 cache 与 SLC2 之间分流。
  • 实施期间现有 GPUShader::Create(MemoryReadStream&) 与固定 permutation API 可继续服务未迁移的旧引擎资产；新资产只创建 ShaderProgramInstance。
  • 新对象内部仍可复用后端现有 GPUShaderProgramVS/PS/CS...Vulkan 作为 VkShaderModule 所有者，但不读取其旧 ShaderBindings 或 SpirvShaderDescriptorInfo。
  • 新 Program 路径稳定后，再逐调用点替换旧 GetVS(name, permutationIndex) 组合；这属于实施迁移步骤，不在新 API 中增加 Legacy fallback。

2. Program、Target 与 Variant 选择

加载

  1. 使用严格 SLC2Reader 解析完整文件；失败时整份 Artifact 不可见。
  2. 按 ProgramId 建立字典，但保留 programs[] 的原始确定性顺序用于诊断。
  3. 每个 Program 内按规范 Target 三元组建立索引；同一 Target 不允许重复。
  4. 每个 Target 内按规范 variant 字符串索引；不计算或保存 variant hash。
  5. Stage code 在创建 GPU 对象前完成 Base64、SHA-256 和 SPIR-V 基础校验。

选择 API

struct ShaderProgramSelection
{
    StringAnsi ProgramId;
    ShaderCompileTarget Target;
    Array<StringAnsi> Defines; // 无序输入，只含宏名。
};

ShaderProgramInstance* CreateProgram(
    const ShaderProgramSelection& selection,
    String& error);
  • ProgramId 精确、区分大小写匹配。
  • Target 使用 platform/backend/shaderModel 精确匹配；不选择“最接近”的 ShaderModel。
  • 运行时根据 SLC2 的 variantGroups 执行与编译期相同的校验和默认补全，再排序并以分号连接。
  • Defines 的调用顺序不影响匹配；未知宏、同组多选、带值宏或不存在的 Variant 返回明确错误。
  • 不做运行时 interface specialization；选择结果必须已存在于 SLC2。

Select(programId, runtimeTarget, requestedDefines):
    program = programsById.FindExact(programId)
    FAIL_IF(program == null,
            "Program not found", programId, AvailableProgramIds())

    canonicalTarget = TRY(CanonicalizeTarget(runtimeTarget))
    target = program.TargetsByKey.Find(canonicalTarget.Key)
    FAIL_IF(target == null,
            "Exact Target not found", canonicalTarget.Tuple)

        program.VariantGroups,
        requestedDefines))
    variant = target.VariantsByCanonicalText.Find(variantText)
    FAIL_IF(variant == null,
            "Variant was not compiled", variantText)

    return ProgramSelection(program, target, variant)

运行时不能向下选择较低 ShaderModel，也不能在 Variant 缺失时即时调用 Slang。

3. ShaderVar 与名称解析

位置模型

struct ShaderVarLocation
{
    uint32 BlockId;
    Optional<uint32> UniformByteOffset;
    Optional<uint32> ResourceRangeIndex;
    Optional<uint32> ResourceIndex;
    uint32 TypeId;
};
  • Struct 成员的 offset 相对于直接父类型；解析器逐层累加。
  • 普通数组：uniform += index × elementByteStride。
  • 资源数组：按 nextResourceIndex = currentResourceIndex × elementCount + index 行优先展平，不修改 set/binding。
  • ConstantBuffer/ParameterBlock 成员通过父块的 block-flavor range 切换到 SubBlockId，并将该子块作为新的位置根。
  • 块本身不会形成数组，因此 Location 不包含 blockIndex 或 block descriptor stride。

路径语法

identifier ("." identifier | "[" unsignedInteger "]")*

允许：
  inputTexture
  material.baseColorTexture
  textures[3]
  materials[2].baseColorTexture

拒绝：
  textures[-1]
  textures[i]
  textures[]
  .material
  material..texture
  • identifier 与 Shader 成员名区分大小写。
  • 数组下标必须是无前导符号的十进制 uint32，且小于 elementCount。
  • 对非 Struct 取成员、对非 Array 取下标、资源类型不匹配都返回包含已解析前缀的错误。
  • 首次解析成功后可缓存“规范路径字符串 → ShaderVarLocation”；缓存由 Reflection 生命周期拥有，不保存到 SLC2。

ShaderVar 路径解析伪代码

ShaderNameResolver.Resolve 计划实现 · 成员偏移相对于直接父类型逐层累加
输入materials[2].baseColorTexture
不变量数组必须固定；块数组已在编译期拒绝
输出ShaderVarLocation
Resolve(path):
    canonicalTokens = TRY(ParsePathGrammar(path))
    IF cache.Contains(canonicalTokens.Text):
        return cache[canonicalTokens.Text]

    cursor = {
        BlockId = reflection.RootBlockId,
        TypeId = RootElementTypeId(),
        UniformByte = 0,
        ResourceRange = 0,
        ResourceIndex = 0
    }

    FOR token IN canonicalTokens:
        type = reflection.Types[cursor.TypeId]

        MATCH token:
            Member(name):
                REQUIRE(type.Kind == Struct)
                member = FindMemberExact(type, name)
                FAIL_IF(member == null, "Unknown member", ParsedPrefix())
                cursor.UniformByte += member.Offset.UniformByte or 0
                cursor.ResourceRange += member.Offset.ResourceRange or 0
                cursor.ResourceIndex += member.Offset.ResourceIndex or 0
                cursor.TypeId = member.TypeId

                IF reflection.Types[cursor.TypeId].Kind == ParameterBlock:
                    mapping = CurrentBlock(cursor.BlockId)
                        .RangeBindings[cursor.ResourceRange]
                    REQUIRE(mapping.Flavor is ConstantBuffer or ParameterBlock)
                    cursor.BlockId = mapping.SubBlockId
                    cursor.TypeId = CurrentBlock(cursor.BlockId).ElementTypeId
                    cursor.UniformByte = 0
                    cursor.ResourceRange = 0
                    cursor.ResourceIndex = 0

            Index(index):
                REQUIRE(type.Kind == Array)
                REQUIRE(index < type.ElementCount)
                cursor.UniformByte = TRY(CheckedAdd(
                    cursor.UniformByte,
                    CheckedMultiply(index, type.ElementByteStride)))
                cursor.ResourceIndex = TRY(CheckedMultiplyAdd(
                    cursor.ResourceIndex,
                    type.ElementCount,
                    index))
                // 数组各元素共享聚合后的 logical range 顺序。
                // 下标只展平 ResourceIndex，不改变 ResourceRange。
                cursor.TypeId = type.ElementTypeId

    location = TRY(FinalizeLeafLocation(cursor))
    cache.Add(canonicalTokens.Text, location)
    return location

多维资源数组逐层执行乘加，因此 a[i][j] 得到行优先下标；所有乘法与加法都必须检查 uint32 溢出。物理 set/binding 只在最终 range mapping 阶段读取。

为何没有 names[]

Type Record 已保存 Struct 成员局部名称，数组位置由下标生成，块出现位置保存局部名称。完整路径由这些信息确定性派生；独立 names[] 会重复身份并可能与类型树产生冲突，因此运行时只维护派生索引。

4. 资源与 Uniform 绑定

Falcor 风格访问 API

ShaderVar ShaderProgramInstance::GetRootVar();
ShaderVar ShaderProgramInstance::FindVar(StringView path);

bool ShaderVar::SetTexture(GPUTextureView* value, String& error);
bool ShaderVar::SetBuffer(GPUBuffer* value, String& error);
bool ShaderVar::SetSampler(GPUSampler* value, String& error);
bool ShaderVar::SetUniform(const void* data, uint32 size, String& error);
ShaderVar ShaderVar::FindMember(StringView name);

  • 名称 API 先解析路径并从根 ParameterBlock 返回 ShaderVar；ShaderVar 的成员与数组访问不重新解析完整路径，二者都按 Type Record 检查资源大类、shape、access 和数组边界。
  • 设置 null 等价于未绑定；当前没有 required/optional 策略，也没有默认资源库。
  • 一次主资源绑定自动覆盖其 auxiliaryRanges 对应的内部 counter 等物理 mapping；用户不能按内部 role 名直接绑定。
  • 固定资源数组支持逐元素绑定；首版不要求“一次传入整段数组”的批量 API。
  • Uniform 写入只复制到对应 ParameterBlock 的 CPU byte array；上传到 GPU buffer 的生命周期和 dirty tracking 不在本设计文档中展开。

ParameterBlock 树与提交快照

ShaderParameterBlock
  blockId
  uniformData[uniformByteSize]
  resources[logicalRange][logicalElement]
  subBlocks[]                         // block-flavor mapping 的唯一子块

ShaderBindingSnapshot (immutable)
  logicalResources[(blockId, rangeIndex, resourceIndex)]
  uniformBuffers[blockId]

每个 Instance 从 rootBlockId 递归构造一棵 ParameterBlock 树。资源状态按逻辑位置保存，不按 Vulkan binding 保存；后端提交时只遍历冻结的 snapshot，并以 rangeBindings 将同一逻辑资源映射到 1～N 个物理 descriptor。

提交前完整性

  1. 第一阶段从 rootBlock 遍历所有可达 block，对每个 simple logical range 的每个元素检查类型兼容且非空，并复制到待冻结 snapshot。
  2. 第二阶段才对 defaultUniformBuffer 物化对应块的 uniform GPU buffer 并加入 snapshot。
  3. 发现首个缺失资源即生成包含完整路径、期望类型、Program/Variant 的错误。
  4. 任何缺失都中止对应 Draw/Dispatch，不提交部分 descriptor writes。

不在 Shader、SLC2 或运行时对象上声明 optional；也不为缺失槽位自动创建白纹理、空 Buffer 或默认 Sampler。

绑定完整性验证伪代码

ValidateAllBindings 计划实现 · 在构造任何 VkWriteDescriptorSet 前执行
输入根 ShaderParameterBlock 树 + Reflection
不变量只要求用户可绑定主 range；辅助 range 从所有者派生
输出冻结的 ShaderBindingSnapshot
ValidateAllBindings():
    snapshot = NewBindingSnapshot()

    // Pass 1：只验证逻辑绑定，不分配 GPU 对象、不写 descriptor。
    FOR blockId IN reflection.ReachableBlocksRootFirst:
        block = reflection.ParameterBlocks[blockId]
        state = FindParameterBlock(blockId)

        logicalRanges = reflection.Types[block.ElementTypeId].ResourceRanges
        FOR rangeIndex, logicalRange IN Enumerate(logicalRanges):
            mapping = block.RangeBindings[rangeIndex]
            CONTINUE_IF(mapping.Flavor != Simple)
            CONTINUE_IF(logicalRange.InternalRole != null)

            FOR resourceIndex IN [0, logicalRange.Count):
                slot = state.ResourceSlot(rangeIndex, resourceIndex)
                FAIL_IF(slot.Value == null,
                    FullResourcePath(blockId, rangeIndex, resourceIndex),
                    ExpectedResourceType(logicalRange))
                TRY(ValidateBoundObjectStillAliveAndCompatible(slot))
                snapshot.AddLogicalResource(
                    blockId, rangeIndex, resourceIndex, slot.Value)

    // Pass 2：全部资源通过验证后，才物化 Uniform Buffer。
    FOR blockId IN reflection.ReachableBlocksRootFirst:
        block = reflection.ParameterBlocks[blockId]
        CONTINUE_IF(block.DefaultUniformBuffer == null)

        state = FindParameterBlock(blockId)
        uniformGpuBuffer = TRY(MaterializeUniformBuffer(
            blockId,
            state.UniformData))
        snapshot.AddUniform(blockId, uniformGpuBuffer)

    return Freeze(snapshot)

两阶段顺序保证缺少资源时不会先创建本次提交专用的 GPU 状态。MaterializeUniformBuffer 的池化与 dirty tracking 属于后续生命周期优化；此处只规定提交前必须得到有效 GPU buffer。

5. Vulkan Pipeline Layout

现有路径的问题

当前 Vulkan 实现通过 DescriptorSetLayoutInfoVulkan::AddBindingsForStage 按 Stage 索引组织 set，并从每个 Stage 的 SpirvShaderDescriptorInfo 构建 Layout。新契约要求所有 Stage 共享一个由 linked Program 反射得到的绝对 set/binding 布局，因此不能继续调用这条路径。

新建 Layout

  1. 从 ShaderProgramReflection 收集并合并全部规范物理 descriptor 记录。
  2. 重算并验证 fingerprint；查找 fingerprint → normalized physical layout 缓存。
  3. hash 命中后深比较记录；完全相等才复用 PipelineLayoutVulkan。
  4. 按 set 分组生成 VkDescriptorSetLayoutBinding，把稳定 descriptorType 和 stageMask 映射为 Vulkan 枚举。
  5. 为 set 索引间的空洞创建空 DescriptorSetLayout，使数组索引与绝对 set 一致。
  6. 创建 VkPipelineLayout，pushConstantRangeCount = 0。

Vulkan Layout 创建伪代码

ShaderProgramLayoutVulkan.CreateOrReuse 计划实现 · 不调用 AddBindingsForStage
输入Validated Reflection 的规范物理布局
不变量绝对 set/binding；StageMask 已合并
输出VkDescriptorSetLayout[] + VkPipelineLayout
CreateOrReuse(reflection):
    physical = TRY(BuildCanonicalPhysicalLayout(reflection))
    REQUIRE(physical.Fingerprint ==
            reflection.PipelineLayoutFingerprint)

    candidates = device.LayoutCache.Find(physical.Fingerprint)
    FOR candidate IN candidates:
        IF DeepEqual(candidate.CanonicalPhysicalLayout, physical):
            return candidate

    setLayouts = []
    FOR setIndex IN [0, physical.SetCount):
        bindings = []
        FOR binding IN physical.BindingsForSet(setIndex):
            bindings.Add(VkDescriptorSetLayoutBinding {
                binding = binding.Binding,
                descriptorType = ToVkDescriptorType(binding.Type),
                descriptorCount = binding.Count,
                stageFlags = ToVkStageFlags(binding.StageMask),
                pImmutableSamplers = null
            })
        setLayouts.Add(device.CreateDescriptorSetLayout(bindings))

    pipelineLayout = device.CreatePipelineLayout({
        setLayouts = setLayouts,
        pushConstantRanges = {}
    })
    result = ShaderProgramLayoutVulkan(
        physical, setLayouts, pipelineLayout)
    device.LayoutCache.Insert(physical.Fingerprint, result)
    return result

空 set 也创建空 VkDescriptorSetLayout，保证 Vulkan set 数组索引与序列化的绝对 set 一致。

6. Vulkan Descriptor 写入

逻辑位置到物理位置

for mapping in rangeBinding.descriptorRanges:
    dstSet          = descriptorSets[mapping.set]
    dstBinding      = mapping.binding
    dstArrayElement =
        mapping.arrayElementBase
      + logicalResourceIndex * mapping.logicalElementStride
  • 资源数组下标只改变 dstArrayElement，绝不加到 binding。
  • SLC2 Schema 2 的 Validator 已保证 arrayElementBase = 0、logicalElementStride = 1、descriptorCount = logical range.count；运行时仍按显式字段计算并断言这些固定值，避免缓存损坏绕过 Reader。
  • 检查最后可寻址元素小于 descriptorCount；越界表示缓存损坏或 Builder 错误。
  • 一条逻辑 binding 的全部物理 mapping 在同一提交中更新，防止组合资源只写一半。
  • descriptorType 决定写入 imageInfo、bufferInfo 或 texelBufferView；类型分支只有一个权威映射函数。
  • Stage mask 只用于 Layout 创建，不改变 descriptor write。

Descriptor 写入伪代码

ShaderDescriptorWriterVulkan.BuildAndCommit 计划实现 · 先构造完整批次，再调用 Vulkan
输入冻结的 ShaderBindingSnapshot + RangeBindings
不变量逻辑数组下标只影响 dstArrayElement
输出完整 descriptor set 更新批次
BuildAndCommit(snapshot, descriptorSets):
    writes = []
    imageInfos = []
    bufferInfos = []
    texelViews = []

    capacity = CountPhysicalWritesByPayloadKind(
        snapshot,
        reflection)
    writes.ReserveExact(capacity.Total)
    imageInfos.ReserveExact(capacity.Images)
    bufferInfos.ReserveExact(capacity.Buffers)
    texelViews.ReserveExact(capacity.TexelViews)

    FOR logical IN snapshot.LogicalResources:
        block = reflection.ParameterBlocks[logical.BlockId]
        mapping = block.RangeBindings[logical.RangeIndex]
        REQUIRE(mapping.Flavor == Simple)

        FOR descriptor IN mapping.DescriptorRanges:
            REQUIRE(descriptor.ArrayElementBase == 0)
            REQUIRE(descriptor.LogicalElementStride == 1)
            REQUIRE(descriptor.DescriptorCount ==
                    reflection.Types[block.ElementTypeId]
                        .ResourceRanges[logical.RangeIndex].Count)
            dstArrayElement =
                descriptor.ArrayElementBase +
                logical.ResourceIndex * descriptor.LogicalElementStride
            REQUIRE(dstArrayElement < descriptor.DescriptorCount)

            payload = TRY(BuildDescriptorPayload(
                logical.Resource,
                descriptor.Role,
                descriptor.DescriptorType))
            writes.Add(VkWriteDescriptorSet {
                dstSet = descriptorSets[descriptor.Set],
                dstBinding = descriptor.Binding,
                dstArrayElement = dstArrayElement,
                descriptorCount = 1,
                descriptorType = ToVkDescriptorType(descriptor.DescriptorType),
                payload = StoreAndReference(payload,
                    imageInfos, bufferInfos, texelViews)
            })

    FOR uniform IN snapshot.UniformBuffers:
        writes.Add(BuildUniformDescriptorWrite(uniform))

    // 之前任何失败都不会产生部分 GPU 更新。
    vkUpdateDescriptorSets(device, writes)
    return Success

组合资源或带 counter 的资源会生成多条 write，但它们共享同一个逻辑绑定所有者。VkWriteDescriptorSet 引用的 payload 存储必须活到 Vulkan 调用返回，且生成指针后不能再扩容；也可先保存 payload 索引，最后统一修补指针。

复用与隔离

可以复用现有 descriptor pool、DescriptorSetLayoutVulkan、VkWriteDescriptorSet 辅助存储和 Vulkan 延迟销毁基础设施；不复用现有按 Stage 的 DSWriter[stage] 索引模型。新 ShaderDescriptorWriterVulkan 以完整 Program 的物理记录和逻辑绑定状态为输入。

容量限制

  • 所有 descriptorCount 在 SLC2 中为正的有限值。
  • 不启用 variable descriptor count、partially bound、update-after-bind 或 runtime descriptor array。
  • 设备 descriptor 上限在创建 Layout 前检查；超限返回 Target/Program/Variant 和具体 set/binding。

7. Pipeline 创建接入

Compute

  1. 选择只有 CS 的 Program Variant。
  2. ShaderProgramInstance 从 Stage code 创建 VkShaderModule，入口名使用 SLC2 entryPoint。
  3. 从 Variant 共享 Layout 获取 ShaderProgramLayoutVulkan。
  4. Compute PipelineState 在收到完整状态描述后，以 CS module 和该 VkPipelineLayout 创建 compute pipeline。
  5. Dispatch 前完成资源完整性检查、descriptor 写入和 set 绑定。

Graphics

  1. 选择同一 Program Variant 内的 VS/PS 及可选 HS/DS/GS。
  2. 为每个 Stage 创建 VkShaderModule；各 VkPipelineShaderStageCreateInfo 只引用 module 与 entryPoint，共享 VkPipelineLayout 设置在 VkGraphicsPipelineCreateInfo 上。
  3. HS/DS 成对、PS 必须存在等契约已在编译和 Reader 阶段验证，Pipeline 层只做防御性断言。
  4. Graphics PipelineState 在光栅、深度、混合、拓扑和渲染目标格式等完整状态到齐后创建 VkPipeline；ShaderProgramInstance 不拥有这些固定功能状态。
  5. descriptor set 只按共享物理 Layout 分配一次，不按 Stage 重复。
  6. Draw 前用同一根参数状态提交所有 Stage 可见资源。

CreateBackendProgram(selection):
    reflection = ShaderProgramReflection.Create(selection.Layout)
    layout = TRY(ShaderProgramLayoutVulkan.CreateOrReuse(reflection))

    modules = {}
    FOR stageRecord IN selection.Stages:
        spirv = TRY(DecodeAndValidateStageCode(stageRecord))
        modules[stageRecord.Stage] = TRY(
            CreateVkShaderModule(spirv, stageRecord.EntryPoint))

    TRY(ValidateModuleStageContract(selection, modules))
    return BackendShaderProgram(layout, modules)

CreatePipelineState(desc, backendProgram):
    IF desc.Kind == Compute:
        REQUIRE(backendProgram.Modules.Keys == { Compute })
        pipeline = TRY(CreateComputePipeline(
            desc.ComputeState,
            backendProgram.Modules.Compute,
            backendProgram.Layout))
    ELSE:
        REQUIRE(backendProgram.Modules.Contains(Fragment))
        REQUIRE(HasValidTessellationPair(backendProgram.Modules))
        pipeline = TRY(CreateGraphicsPipeline(
            desc.GraphicsFixedFunctionState,
            backendProgram.Modules,
            backendProgram.Layout))

    return PipelineState(
        pipeline,
        backendProgram.Layout.PipelineLayoutFingerprint)

PrepareAndBind(commandContext, pipelineState):
    REQUIRE(pipelineState.PipelineLayoutFingerprint ==
            _backend.Layout.PipelineLayoutFingerprint)
    snapshot = TRY(_programInstance.ValidateAllBindings())
    sets = TRY(commandContext.AllocateDescriptorSets(_backend.Layout))
    TRY(_backend.DescriptorWriter.BuildAndCommit(snapshot, sets))
    commandContext.BindPipeline(pipelineState.Pipeline)
    commandContext.BindDescriptorSets(_backend.Layout, sets)

Program 可被多个兼容 PipelineState 复用；fingerprint 检查阻止把参数绑定到不兼容的 Pipeline Layout。descriptor 分配复用、跨帧缓存和延迟销毁仍是生命周期非目标；该流程只规定正确性顺序。
