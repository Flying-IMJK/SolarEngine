前置条件与工程边界 v2

Slang 已由 SolarEngine 工程接入，本设计只定义 Shader 编译系统如何使用它。

1. Slang 前置条件

SolarEngine 已提供可直接使用的 Slang 编译 API。Shader 编译系统实现时可以直接包含 Slang 公共头并调用公共 API；本设计不负责 Slang 的工程接入、构建、部署或版本管理。

实施边界： 不新增或重写任何 Slang 工程接入脚本；不重新设计 CMake 接入或动态库部署策略。

公开入口边界

namespace SE
{
    class ShadersCompilation
    {
    public:
        static bool Compile(ShaderCompilationOptions& options);
    };
}
  • 旧入口继续服务旧资产。
  • 新路径新增 Slang-only 请求/结果结构，并由 SE::ShadersCompilation 暴露新入口或新调度分支。
  • 新入口只接受 Slang Shader 资产，不做语言嗅探和自动 fallback。
  • 旧 ShaderCompilationOptions 不作为新系统完整设计输入。

3. 编译侧与运行时边界

编译侧可以做

  • 创建 slang::IGlobalSession。
  • 每次请求创建独立 slang::ISession。
  • 加载根 Module。
  • 读取 Program marker Attribute。
  • 调用 findAndCheckEntryPoint。
  • 链接 IComponentType。
  • 读取 ProgramLayout。
  • 生成 ShaderReflectionIR。
  • 写入并 self-read SLC2。

运行时侧不能做

  • #include <slang.h>。
  • 链接或调用 Slang。
  • 保存 Slang 反射指针。
  • 从 SPIR-V 二次反射来补充布局。
  • 参与 Program 发现、Variant 规划、Target codegen 或 SLC2 写入。

3. 引擎基础设施优先原则

Shader 编译系统实现默认使用 SolarEngine 已有基础设施，不直接绕过引擎平台层。

  • 路径规范化、合并、相对路径消解、文件/目录存在性判断使用 FileSystem。
  • 文件读取/写入使用 File。
  • 文本与第三方 const char* 边界使用 String / StringAnsi / StringView；第三方 API 需要 const char* 时，以 StringAnsi 持有桥接对象生命周期。
  • 动态数组、字节缓冲和集合优先使用 List / DataContainer / 引擎集合。
  • Hash、Base64、JSON、日志、断言、线程与原子操作优先使用引擎提供的方法。
  • STL 只允许作为第三方 ABI 无法避免的局部桥接或引擎尚无等价能力时使用；不得作为路径语义、文件 IO、持久化格式、日志、线程、内存生命周期的默认实现。
  • 控制流分支必须显式使用 {}，包括单语句 if / else / for / while；新增 Shader 编译路径不允许无括号当行分支。

4. Slang 生命周期

Process:
  IGlobalSession

Compile request:
  ISession
    target desc
    preprocessor macros
    SlangShaderFileSystem

Linked Program:
  IComponentType
    target code
    ProgramLayout
    diagnostics

Serialized:
  ShaderReflectionIR
  SLC2
  • IGlobalSession 由编译服务进程级持有。
  • 每次编译请求创建独立 ISession。
  • ShaderCompileRequest 不携带 SearchPaths；根文件目录、import/include 查找和未来引擎虚拟路径映射均由编译侧 SlangShaderFileSystem 负责。
  • SlangShaderFileSystem 的路径操作和文件读取必须走 FileSystem / File；不得使用 std::filesystem、std::ifstream 或调用方传入 search path。
  • Slang COM 对象使用 Slang::ComPtr。
  • 不把裸反射指针保存到请求之外。
  • ProgramLayout 生命周期不超过 linked component；运行时需要的数据必须在编译期复制进 ShaderReflectionIR。

5. 验收

  1. 编译侧源码可直接 include Slang 公共头。
  2. 新 Slang 编译入口不调用旧 Parser。
  3. 新 Slang 编译入口不调用旧 RequestCompiler(ShaderProfile)。
  4. 编译侧可以在没有 GPU 设备和 Vulkan runtime 的情况下完成 Compile-only 闭环。
  5. 运行时模块不依赖 Slang 头文件或 Slang 反射对象。
  6. 已生成 SLC2 可由无后端 SLC2Reader 读取和校验。
