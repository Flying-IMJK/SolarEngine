0. 第二版迭代说明

第二版保持系统设计契约不变，重点把第一版的职责说明转换为可直接指导编码的实现算法。每条主链路补充伪代码、输入/输出、失败边界和不变量；伪代码中的类型与文件名表示计划实现，不代表 SolarEngine 当前已经存在这些 API。

现有事实：已在 SolarEngine/Slang 源码中确认 计划实现：本实施方案新增 过渡路径：只为保持实施期间可构建 后续设计：当前明确不实现
新增算法说明依赖构建、编译事务、Program 发现、Variant 规划和联合链接。
新增数据转换Slang Layout → ShaderReflectionIR、严格验证、SLC2 确定性读写。
新增运行时流程Program/Variant 选择、ShaderVar 路径解析、资源完整性验证。
新增 Vulkan 流程共享 Pipeline Layout、逻辑资源到物理 descriptor 的映射与提交。
新增测试骨架Slang API 编译/链接 probe、反射 smoke、编译 fixture、SLC2 mutation、Vulkan validation 功能测试。
表达优化明确区分当前代码事实、计划类型、过渡实现和非目标。

伪代码约定与总流程

  • Result<T> 表示成功值或一个带上下文的错误；TRY(x) 在失败时立即向上返回。
  • FAIL(...) 不提交部分状态；公开编译结果最终仍只有 Success/Failed、CompileMessage 和 SLC2Data。
  • StableSort、Canonical* 表示系统设计已经确定的稳定排序与规范编码。
  • 伪代码省略引用计数、分配器和日志样板，但不省略所有权、失败边界或原子提交位置。
编译独立闭环与运行时消费流程 计划实现 · SLC2 是两部分之间唯一持久化边界
输入Slang Shader Resource + Targets + VariantSelections
不变量编译功能不依赖运行时对象、GPU 设备或 Vulkan descriptor writer
输出Compile-only 阶段输出完整 SLC2；运行时阶段只消费 SLC2
CompileOnly(request):
    compileResult = CompileShaderResource(request)
    if compileResult.Status == Failed:
        return FAIL(compileResult.CompileMessage)

    // 使用共享、无 Slang、无 Vulkan 依赖的 Reader/Validator 自检。
    artifact = TRY(SLC2Reader.ReadAndValidate(
        compileResult.SLC2Data))
    TRY(CompareSemanticManifest(artifact, request.ExpectedManifest))
    return compileResult.SLC2Data

LoadAndCreate(slc2Data, selection, bindings):
    artifact = TRY(SLC2Reader.ReadAndValidate(slc2Data))
    selection = TRY(artifact.Select(
        selection.ProgramId,
        selection.Target,
        selection.Defines))

    program = TRY(ShaderProgramInstance.Create(selection))
    TRY(program.BindResourcesByName(bindings))
    return program

CompileOnly 是 P0-P3 的独立验收闭环：它可以在没有 ShaderProgramInstance、Vulkan runtime、GPU 设备和资源对象的情况下测试 Program/Variant/Target、IR、SLC2、Reader、fingerprint 与确定性。LoadAndCreate 从已存在的 SLC2 开始，解码 Stage code，并创建或复用共享 Pipeline Layout；完整固定功能状态到齐后由 PipelineState 创建 VkPipeline。Draw/Dispatch 的 PrepareAndBind 再执行绑定验证、descriptor 原子写入与命令绑定。运行时不会保留或重新创建 Slang Session。

1. 目标与交付边界

本文件集把已完成的系统设计转换为可实施的模块、类、调用顺序、阶段和验收项。系统契约仍以设计文档为准；这里不重新开放已确认决策。

新编译入口独立 ShaderCompileRequest/Result；不继承围绕 ShaderMeta 和旧二进制 cache 的 ShaderCompiler。
Slang 边界只存在于离线编译模块；SLC2 Reader、runtime reflection 和 Vulkan 后端不链接 Slang。
编译独立闭环P0-P3 必须能在没有运行时 Program、Vulkan 设备和 descriptor writer 的情况下完成测试；其验收产物是完整 SLC2 和语义 manifest。
事务粒度一个请求只返回完整 SLC2 或失败；任何 Program/Target/Variant/Stage 失败都没有部分数据。
Program Layout同一 Variant 的全部 Stage 联合链接并共享一份 IR 和 Pipeline Layout。
运行时绑定按名称和固定数组下标定位逻辑资源，再经 range mapping 写入 1～N 个 Vulkan descriptor。
资源缺失提交前报错并中止 Draw/Dispatch；不声明 optional、不自动补默认资源。
首个纵向切片Vulkan Compute：Texture/Buffer/Sampler 名称绑定和 validation layer 零错误。
明确后置Cook/发布、DependencyIndex、默认资源、动态 specialization、Push Constant、无界 descriptor 和 runtime lifecycle 优化。

实施原则

  • 新路径显式接入，不通过 cache 内容、资产版本、ShaderProfile 或语言字段自动回退。
  • 共享稳定数据结构不含 Slang/Vulkan 原生指针和枚举；适配只在边界模块发生。
  • Compiler Writer 与 runtime Reader 使用同一个 Validator；成功产物必须 self-read。
  • 先写纯算法测试和负向 fixture，再接 GPU；不使用硬编码 binding 让演示先跑起来。

2. 现有接入点与必须替换的假设

当前代码现有假设新路径处理
ShadersCompilation.cpp · Compile运行旧 Parser，生成 ShaderMeta，再按 ShaderProfile 请求后端编译器。新增 request/result 重载，直接进入 Slang 编译事务。
ShaderCompiler.h/.cpp逐 Stage/permutation 写 GPU cache v13 二进制。不作为新基类；新协调器聚合 Program/Target/Variant 并写 SLC2 JSON。
Vulkan/ShaderCompilerVulkan.cppglslang + SPIR-V 头部中的 descriptor info。Slang 直接生成 SPIR-V；编译期生成独立 ShaderReflectionIR。
Graphics/Shaders/GPUShader.cpp按 Stage name + permutationIndex 读取旧二进制和固定 CB 槽。新 Slang 资产显式加载 SLC2，并选择完整 Program/Target/Variant。
DescriptorSetVulkan.cpp按 Stage 组织 descriptor set，部分位置由 descriptorIndex 推导 binding。使用 SLC2 的绝对 set/binding 和合并 Stage mask 构建共享 Layout。
GPUPipelineStateVulkan.cpp从每 Stage DescriptorInfo 合成 Layout 和 Writer。完整 Program instance 直接提供共享 Layout 和 Program 级 descriptor writer。

只替换 Shader 编译器调用不足以完成目标。现有 Vulkan runtime 的 Stage-set 模型也必须建立一条新的 Program-shared Layout 路径。
